# Translate Luminary LUNAR_LANDING_GUIDANCE_EQUATIONS

Lane F (LM powered flight and DAP). Milestone `lm-llge`. How the routines are made and checked: `docs/INTERP-COMPILE.md`.

`Luminary099/LUNAR_LANDING_GUIDANCE_EQUATIONS.agc` (`src/lm_llge.c`, generated by `tools/interp_compile.py lm-llge`) is native C on the control-transfer ABI except the two `WOR CHAN13` writes to an output channel. The file is the landing guidance of P63 to P67: the guidance pass the SERVICER reaches through AVEGEXIT (LUNLAND, ?GUIDSUB and GUIDSUB with the phase tables NEWPHASE to WHATALM), the P64 redesignation (REDESIG, REDESMON and its counter in PITFALL's bank), the time-to-go and target logic (TTFINCR, TTF/8CL with the ROOTPSRS polynomial root finder, QUADGUID, CGCALC and the EXTLOGIC phase switch), the P65 to P67 starts and the rate-of-descent task (STARTP66, STARTP67, RODTASK, RODCOMP, VHORCOMP), the guidance displays (P63DISPS, P64DISPS, VERTDISP, TDISPSET) and FASTCHNG.

248 routines start at the entries (LUNLAND, ?GUIDSUB, GUILDEN, PITFALL, DESCBITS, P63DISPS -2, INTPRETX, ROOTPSRS, FASTCHNG, RODTASK, STARTP66, STARTP67, P65START, STARTP64, REDESMON), at every point another file returns to, at words nothing in the file reaches (`resume_orphans`), and at every word after a DANZIG (`resume_keys`): the guidance runs as a job, so a DANZIG can find a job waiting and stop at CHANG2, and the Executive resumes the job there. `RTB LOADTIME` is native (`src/rtb_angles.c`), and `RTB NORMUNIT` is too (`src/lm_normunit.c`, the NORM front of `src/rtb_vector.c` and UNIT's phases of `src/rtb_unit.c`).

The channel reads are native (`channel_inputs`, `-DIRC_INPUTS`): `READ CHAN30` (STERN, in GUILDEN) and `RAND`/`READ CHAN31` (the mode-control and hand-controller checks in STABL?, RATESTOP, PITFALL, REDESMON and its counting loop) read the latched inputs of the run (`agc_input_channels.h`), which the differential draws per case and hands to yaAGC as the same channel values. That also drops the 10 routines that only existed to resume after a refused read.

Not translated: `WOR CHAN13` with its `EXTEND` in STARTP64 (31,2635) and in REDESMON's RESETRPT (11,2336). They wait for the shared output-channel model (Lane D1). The compiled routines stop with `EXEC_OUT_OF_SCOPE` at them, and the source map records them as untranslated with the spec's reason. The file stays partial until they are translated, and the earlier P66 work in `docs/port-coverage.json` stays listed beside this one.

## WCHPHOLD

DISPEXIT's `INDEX WCHPHOLD` / `TCF WHATDISP` with WCHPHOLD -1 lands on WHATEXIT's `TCF EXNORM`, which loops back to DISPEXIT for ever, so yaAGC never reaches a stop. The program only runs IGNALG (-1) with FLUNDISP set, so DISPEXIT never gets there in flight; cases entering CGCALC to P63DISPS and 1406P00 to FASTCHNG keep WCHPHOLD on 0 to 2 (`range_states`).

## Compiler changes

`tools/interp_compile.py` gained `index_tcf`, `basic_fixed_index`, `index_erasable`, `intpret_via`, `in_file_returns`, `returns` 0, `rtb` stop codes, `TC A`, `INCR BBANK` and `index_carry16` (listed in `docs/INTERP-COMPILE.md`). Every other spec still regenerates byte-identical (`--check`). `cm-p34-p35` differs with the base compiler too, so that is not from this change.

`index_carry16` fixes a C64-only fault in the generated `ixw()` (INDEX K): its end-around carry tested bit 16 of an `unsigned`, which is 16 bits on the 6502. There, `INDEX WCHPHASE` with WCHPHASE -1 lands one word low, and the indexed TCF table refuses. The host builds were right, so only the C64 diagnostic showed it. Other specs keep the old form until the steward decides on a shared regeneration.

## Evidence

Hashes: `evidence/lm-llge/SHA256.json`.

- **Source map.** `lm-llge-source-map.json` lists all 991 words with the routine that compiles each, or the reason it is not compiled (3 words: both `EXTEND`s and the STARTP64 `WOR`; RESETRPT's `WOR` word is owned by the routine that compiles it reached without `EXTEND`, as a `TC`).
- **Independent assembly comparison.** `make lm-llge-differential`: 512 states for each of the 248 routines (126,976 cases, with the flight edge values of `tools/edge_cases.py` in a quarter; WCHPHASE and WCHPHOLD hold a phase, -1 to 2, and X1 is -TARGTDEX as INTPRETX sets it; channels 30 and 31 are random) run the unmodified Luminary099 rope in yaAGC (with the hardware divide) to the same stop. All 125,429 compared cases equal it in Z, all 2,048 erasable words and the interrupt-enable state. The 1,547 cases that reach a `WOR CHAN13` are listed in `lm-llge-proof.json` as `waiting_for_io_channels` and are not compared.
- **Host and sanitizer results.** `make test-lm-llge sanitize-lm-llge` run the 3,920 frozen cases (every 32nd).
- **C64 execution results.** `make vice-lm-llge` runs 34 diagnostics (routine groups that fit below $c000) with 337 cases chosen by `tools/c64_row_cover.py` over every 8th host case (`cover_stride`). They take 2,225 of the 2,347 branch arcs (gcov, every linked source) the traced host cases take (`lm-llge-c64-cover.json`). The rest belong to guidance passes whose whole runs reach more code than one diagnostic holds (`c64_cover_partial`); the proof lists them (`c64_missed_arcs`).
