# Checked native module directory

The metadata payload at native module148 contains the frozen111-module recurrence directory. The resident retains its one explicit bootstrap descriptor, including loaded size and CRC. The unchanged loader checks that payload before invocation. Metadata copies the complete requested descriptor and a bounded NUL-terminated filename into resident storage. No table, filename or callback pointer into the replaced metadata slot escapes.

`native_registry_call` owns one producer-exclusion token across metadata lookup, its normal C return, the actual stage load and the stage's normal C return. Every load still uses the original ID, size, header and CRC checks. Lookup alone cannot change the canonical2,048-word image or source I/O. An unknown ID, missing file, checksum error or malformed record invalidates the lease and preserves the caller's result. This extends the existing accidental disk-corruption checks; the compiled bootstrap and initialized native binding are caller-owned.

The dedicated target allocation is `$c600..$c63f`. Its descriptor/name/request/valid record is statically bounded by64bytes. It does not overlap the frozen fixture `$c000..$c03f`, mailbox `$c080..$c085`, Executive `$c100..$c387`, task reservation `$c388..$c3d3`, or binding/runtime `$c400..$c5ff`. Canonical `$7000..$7fff`, overlay `$8000..$bfff` and software stack `$c800..$cfff` remain unchanged. The initialized loader, bootstrap descriptor and filename, registry object, producer hooks and lease must outlive each call. The lease is scratch metadata, overwritten by the next lookup; callers must not retain its previous contents as a second directory.

Host strict and ASAN/UBSAN tests compare all111 complete descriptors, bounded names, unknown and null IDs, duplicate/malformed records, stale output, reentrancy, short/long/header/checksum/I/O failures and enabled/masked exclusion restoration. The standalone stock-ROM C64 diagnostic queries all111 records twice, checks the directory digest and every canonical word, then exercises stale/null/CRC/missing-file/recovery paths. The separate full recurrence derivative loads arithmetic, scheduler and basic stages through the new directory while checking the original310 raw source checkpoints.
