# Comanche alarm return and overflow distinction

`cm_alarm_complete` is an additive wrapper for actual ALARM5650, VARALARM5764, CURTAINS5757 and BORTENT5655. It preserves all existing alarm kernel and caller-image bytes. A normal BORTENT callerQ05720 executes RELINT and returns to address05721. That address is also the entry of POODOO. The frozen `cm_alarm_image` wrapper had used the final PC alone to restore incoming IRQ on an overflow handoff, so a normal return to this address incorrectly retained incoming IRQ0. The corrected wrapper distinguishes the actual TS FAILREG+2 overflow resultA=+1/raw-1 from a normal returnA=ordinary callerQ. Normal returns retain IRQ1; genuine overflow preserves the BORTENT caller's IRQ, since BORTENT itself does not INHINT.

`tools/cm_alarm_return_collision_audit.py` replays both incoming virtual IRQ cases against the unchanged frozen helper and fresh original source. Its retained two-state captures reproduce exactly one difference: the IRQ0 case's returned virtual IRQ. The corrected helper matches every field. There was no C64 target failure. The earlier uncommitted ALARM2 draft exposed this collision while calling the frozen wrapper; ALARM2 now calls the unchanged recording kernel with the same actual TS-result distinction. Historical artifacts remain unchanged.
