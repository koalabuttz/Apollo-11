# Translate Luminary R63

Lane F (LM powered flight and DAP). Milestone `lm-r63`. How the routines are made and checked: `docs/INTERP-COMPILE.md`.

`Luminary099/R63.agc` (`src/lm_r63.c`, generated by `tools/interp_compile.py lm-r63`) is native C, every word of it. R63 is Verb 89, the rendezvous final attitude: it asks the crew for the axis (+Z or +X) to point at the CSM, advances both state vectors to now (CSMCONIC, LEMCONIC), computes the line of sight in stable-member coordinates, finds the gimbal angles with VECPOINT, displays the FDAI ball angles (V06 N18), and on PROCEED clears 3AXISFLG and calls R60LEM for the maneuver.

## Scope

| Luminary099 | Source | Leaves at |
|---|---|---|
| 26,2022 V89CALL to 26,2122 | V89CALL, V89RECL, ALINEX, V89CALL1, ALINEZ | BANKCALL (R02BOTH, GOFLASH, BALLANGS, R60LEM), DOWNFLAG, ENDEXT, CALL CSMCONIC, LEMCONIC and VECPOINT, RTB NORMUNIT |

30 routines start at the entries (V89CALL, V89RECL), at every point another file returns to (BANKCALL and the three GOFLASH returns: terminate, proceed, data in), and at every word after a DANZIG (`resume_keys`): R63 runs as a job, so a DANZIG can find a job waiting and stop at CHANG2, and the Executive resumes the job there.

After V89CALL's display (26,2063), most cases keep OPTIONX +1 = 1, the Z axis the crew proceeds with, and the rest take 2 (X). So `BZF ALINEZ` is compared both ways (`states`).

`RTB LOADTIME` runs the native body in `src/rtb_angles.c`. `RTB NORMUNIT` has no native body yet; the run ends at it, as it does at the outside interpretive calls and basic routines.

V89 runs in flight, so flight builds skip the entry checks' whole-image scan (`trusted_image`) and address the fixed image directly (`image_w`); host tests and the C64 diagnostic keep the scan. `index_carry16` keeps INDEX's end-around carry right on the 6502 (`docs/INTERP-COMPILE.md`).

## Evidence

Hashes: `evidence/lm-r63/SHA256.json`.

- **Source map.** `lm-r63-source-map.json` lists all 65 words with the routine that compiles each; none is untranslated.
- **Independent assembly comparison.** `make lm-r63-differential`: 512 states for each of the 30 routines (15,360 cases, with the flight edge values of `tools/edge_cases.py` in a quarter) run the unmodified Luminary099 rope in yaAGC (with the hardware divide) to the same stop. All 15,360 equal it in Z, all 2,048 erasable words and the interrupt-enable state; none is refused.
- **Host and sanitizer results.** `make test-lm-r63 sanitize-lm-r63` run the 960 frozen cases (every 16th).
- **C64 execution results.** `make vice-lm-r63` runs one diagnostic with 35 cases chosen by `tools/c64_row_cover.py`: together they take all 445 branch arcs (gcov, every linked source) that the 15,360 host cases take.

## Tool change

`tools/interp_routine_differential.py`: with `'c64_rows': 'cover'`, the fit probe for each routine set now knows the file's KEEP words before it builds, so a spec can use the branch-outcome cover (R63 is the first that does).

NEWJOB positive at a DANZIG is not a refusal: the run stops at CHANG2, as the original does, and that stop is compared with yaAGC. The word after it is a registered key, so the resumed job runs natively.
