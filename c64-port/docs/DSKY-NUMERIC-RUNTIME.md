# Native numeric keyboard interrupt lifecycle

`dsky_keyboard_number_mappings` binds actual LM CHARIN2077/060101 to the independently verified numeric body and real native Executive FINISH. It uses the existing canonical keyboard binding. The input transport executes real C64 KERNAL GETIN, maps PETSCII to channel15, then complete native hardware KEYRUPT/KEYCOM/RESUME source stores. The ordinary BRUPT word is retained as data. Native ADVAN/NUDIRECT starts the admitted basic job; after CHARIN reaches actual ENDOFJOB, its C frame returns before the real native completion/exchange runs. No fake scheduler callback or AGC opcode decoder is used.

This mapping supports the NUM domain; the separately verified V/N mapping remains available for its input domain. A production union must select compiled body/stage mappings explicitly. Other keyboard operator commands and the complete flight application's input loop remain further work. Source producers are excluded at the hardware frame, start and native body boundaries, preserving the caller's IRQ token. The canonical flight image is the only persistent original state.

An unchanged original-engine oracle requests the actual hardware key interrupt at idle ADVAN3214, records complete source states after real RESUME, at actual CHARIN entry, and at actual ENDOFJOB.
