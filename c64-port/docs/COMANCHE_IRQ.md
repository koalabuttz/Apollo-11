# Comanche 055 C64 IRQ publication and foreground admission

`cm_irq` is a separate MIT adapter around the verified seven-core CM native runtime. It holds a pointer to that runtime, a four-entry native request queue, and up to sixteen callback proxies. It owns no second copy of core/VAC/Executive words. Bind once before running, with the source stopped; original mapping tables are immutable and all referenced storage must outlive the adapter. Calls thereafter use the adapter API. Queue requests always admit basic jobs; existing typed basic/interpretive mappings remain available to the runtime.

The single non-nested ISR writes every request payload field, then publishes one volatile byte ticket. Foreground admission copies the payload under a restoring exclusion hook and calls the already qualified Comanche admission translation. An unconsumed failed head remains queued. Queue overflow latches and preserves accepted payloads, stopping admission before mutation; rejected-count saturation and ticket wrap are explicit. Invalid mappings, helper faults and pending source alarms stop callback completion/exchange. This synchronization is an IRQ mask/copy contract, not a C11-thread queue.

The callback proxy preserves the existing CM trampoline implementation. It restores the caller's previous IRQ state before calling the original C callback, masks on return, delivers queued requests, then returns its C frame before the verified trampoline epilogue exchanges contexts. Explicit safe-point polling within a callback is also supported. Callback data, core/VAC payloads and typed mappings retain their existing identities. Recursive step/start calls are rejected. The CM Executive original source requires scheduling changes to exclude interrupt interference; the native ISR publishes requests rather than changing Executive words, and the foreground masks admission and context exchange. This is a native platform adaptation, not an AGC instruction decoder or a translation of every CM interrupt handler.

The C64 gate uses the established LLVM-MOS/KERNAL restore contract. All 32 compiler imaginary registers, the software stack pointer and interrupted A/X/Y/P are preserved; decimal mode is cleared for the C producer and restored by RTI. The producer has an isolated 256-byte dynamic stack. Source and adapted platform files are checked byte-for-byte after reversing only CM symbol and queue-type substitutions, recorded in `evidence/cm-irq-platform-audit.json`. Builds use `-fno-static-stack -mlto-zp=0`; no extra zero-page spills are allowed. Source removal restores the previous KERNAL IRQ vector and raster ownership. This bounded diagnostic supports stock KERNAL/raster use and requires exclusive raster ownership; it supplies no NMI or production mission timer service.

Independent host yaAGC execution of original CM admission verifies 512 valid published payload cases against every one of 312 owned words and result. Sixteen guard words and source alarm boundaries are checked. Eight real sequential native callback sequences produce 64 complete states matching original CM dispatch assembly. Host checks repeat those callbacks with ordinary/typed mappings and explicit/automatic delivery: 32 sequences / 240 observed checkpoints. Restoring nested guards, retained failed heads, overflow, saturated rejects, invalid mappings, callback helper faults and masked-caller preservation pass, as do ASan/UBSan. Admission snapshot SHA256 is `a63460f812f92be78d5cff5a12cd1aa5c4dff9507134a88f084832e0ff5dbaed`; sequence snapshot SHA256 is recorded in the generated vectors. The oracle links no native scheduler or arithmetic code.

The original Executive fixture is pinned to Virtual AGC `1b5d6474841a7ab53237ead070f76f35f162f68d`; its historical indentation repairs and whole-rope equality proof are described in COMANCHE_EXECUTIVE.md. Original CM interpreter and dispatch provenance are described in COMANCHE_DISPATCH.md. Historical originals are untouched; GPL reference machinery remains host-only.

Hardware stack extents are below `$01f2`; software extents are below `$d000`. No measured stack reaches the bottom of its instrumented range. All seven actual ISR entry/exit marker pairs are captured; observed ISR cycles are 2566, 2150, 2135, 2135, 2135, 2135 and 1959. The hardware tests include a deliberately poisoned 32-register probe with D/I/A/X/Y canaries, an interrupted live C frame and independently computed 32-bit arithmetic, payload byte checks, full Executive immutability during ISR, restoring foreground guards, automatic callback-return delivery into a typed runtime, queue overflow preserving all four accepted entries, KERNAL jiffy coexistence and IRQ vector restoration. Finite fingerprints can collide; complete host state comparisons are primary evidence, with complete target samples and callback states as supplemental checks. These resource measurements establish bounded diagnostics, not complete-application fit or WCET.

Reproduce with `make cm-irq-differential`, `python3 tools/cm_freeze_irq.py`, `make test-cm-irq sanitize-cm-irq c64-cm-irq`, then `python3 tools/cm_irq_vice_test.py --stage admission --vice /path/to/x64sc --rom-dir /path/to/C64 --data-dir /path/to/vice` and again with `--stage irq`. Before parent integration, use `-f Makefile -f tools/cm_irq.mk`. The differential independently executes the original CM dispatch code to refresh its callback source corpus before comparison. ASan leak scanning is disabled because ptrace is blocked in this container. Evidence is `evidence/cm-irq*`, with generated SHA256 records in `build/cm-irq-evidence.sha256`.
