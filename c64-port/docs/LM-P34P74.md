# P34/P74: transfer phase initiation (TPI)

Lane E. Milestone `lm-p34p74`.

## Scope

From `Luminary099/P34-35_P74-75.agc`, bank 35 `02545`-`02724`: 112 words on
112 source lines. Eighteen basic routines are keyed by Z. Sixteen
interpretive routines are keyed by LOC under BANKSET at NEWOPS. All use the
control-transfer ABI (`include/agc_transfer.h`, `docs/NATIVE_TRANSFER_ABI.md`).
`include/lm_p34p74_routines.h` lists each entry.

- **Entry (basic):** P34 and P74 go through AVFLAGA or AVFLAGP. P34/P74A
  calls P20FLGON and shows V06N37 (TTPI) through VNPOOH. It then loads
  130DEG into CENTANG and zero into NN, calls DISPLAYE, and enters INTPRET.
- **TPI time (interpretive):** clears ETPIFLAG and stores TTPI into TIG.
  With ELEV nonzero it sets ETPIFLAG (BZE). Either way it calls SELECTMU.
- **Search loop (interpretive):** P34/P74C zeroes NOMTPI and sets ITSWICH,
  clearing it again unless ETPIFLAG is set. INTLOOP advances both vehicles to TTPI + NOMTPI (PRECSET)
  and calls S33/34.1. Its return either goes to SWCHCLR (BZE) or exits to
  the 611 alarm. SWCHCLR loops (BONCLR ITSWICH) or exits to the displays.
- **Alarm (basic):** TC ALARM with OCT 611, then V05N09 through GOFLASH.
  Terminate goes to GOTOPOOH, proceed to P34/P74A, and recycle back to the
  alarm.
- **Displays (basic):** DISPLAYE for ELEV and CENTANG, or V06N37 through
  VNPOOH, each followed by P34/P74E's INTPRET.
- **Transfer (interpretive):** after P34/P74E's INTPRET, it sets up
  TIMETHET:
  - X1 from RTX1;
  - CSTH and SNTH from CENTANG (COS, SIN);
  - RVEC and VVEC from RPASS3 and VPASS3, scaled by VSR* 0,2;
  - RVSW set.

  TIMETHET's return stores INTIME and TPASS4 = TTPI + T, then calls
  S34/35.2. Its return stores DELVTPI = |DELVEET3| and
  DELVTPF = |VPASS4 - VTPRIME|, pushes RACT3 and calls PERIAPO1 with
  VIPRIME. Then SHIFTR1, POSTTPI and TIG, and V06N58 through VNPOOH.
- **Main loop (interpretive):** S34/35.5, VN1645, then GOTO P34/P74C.

Each run ends at the first point outside these routines
(`tests/lm_p34p74_cases.c`, `lm_p34p74_stop`). That is one of:

- AVFLAGA, AVFLAGP or P20FLGON (P32-P35_P72-P75);
- DISPLAYE or VNPOOH (lm-p34-transfer);
- ALARM, BANKCALL, GOTOPOOH or INTPRET;
- ABVAL's POODOO1 (alarm 1302);
- a NEWOPS outside `35,2562`-`2724`: SELECTMU, PRECSET, S33/34.1,
  TIMETHET, S34/35.2, PERIAPO1, SHIFTR1, S34/35.5 or VN1645.

Every interpretive pair is compiled with the shared bodies
(`src/lm_interp_steps.c`, `src/lm_interp_orders.c`). SIN and COS run the
original bodies (`src/sband_trig.c`). ZEROVECS is read from the certified
rope. V06N37, V06N58, 130DEG, P30ZERO and V05N09 are literals that the
source map checks against the fresh rope. Each basic instruction is one
`ai_*` register effect on the image, in source order.

Admission is as in `docs/LM-P35.md`. Interpretive routines admit a
canonical NEWOPS image at their LOC in FB 35 meeting all of these
conditions, and otherwise return `EXEC_OUT_OF_SCOPE` with the image
unchanged:

- EB and BB coherent, with BANKSET = BB;
- INTBIT15 set;
- EDOP, ZERO and NEWJOB zero;
- MODE `+0`, `+1` or vector;
- the VAC one of the five, with PUSHLOC no further than 40D into it;
- IRQ 0 or 1, and an allowed SUPERBNK;
- every word 15 bits.

Basic routines admit Z at their entry in FB 35, with EB and BB coherent,
ZERO zero, IRQ 0 or 1, an allowed SUPERBNK and every word 15 bits.

## Evidence

Hashes are in `evidence/lm-p34p74/SHA256.json`. Bulk files are assets of
the `evidence-lm-p34p74` release (`python3 tools/evidence.py fetch lm-p34p74`).

- **Source-to-native map and independent assembly comparison.**
  `python3 tools/lm_p34p74_source.py` reassembles the unchanged file with the
  pinned yaYUL. The rope equals the certified fixed-data rope.
- **Oracle.** `tools/lm_p34p74_reference.c` (GPL, host only) runs the
  unchanged Luminary099 in the pinned yaAGC hardware-DV variant from 17408
  entries, 512 per routine, to the same stops.
  - The entries sit over poisoned debris with any times, vectors and flags.
  - ELEV is zero in one P34 start in two, and MPAC in one S33/34.1 return in
    two, so both BZE outcomes run.
  - EB is SUBEXIT's bank three times in four.
  - They cover every VAC, MODE, PUSHLOC, IRQ and allowed SUPERBNK setting.

  `tools/lm_p34p74_differential.py` requires every native trampoline run to
  produce the same 2048 erasable words, interrupt state and SUPERBNK. It pins
  the stream identity (`lm-p34p74-source-stream.json`, SHA256
  `2e268198...a0daa7`) and archives the stream
  (`lm-p34p74-reference.snapshots.bin.xz`). `lm-p34p74-proof.json` lists the
  stops per routine.
- **Host and sanitizer results.** Run `make test-lm-p34p74 sanitize-lm-p34p74`.
  The strict build and the ASAN/UBSAN build each pass 17829 checks:
  - all 17408 frozen digests;
  - every run ending at one of the stops;
  - 350 admission guards: EB, BB, FB, ZERO, 16-bit words, SUPERBNK and IRQ
    for every routine, and VAC, MODE, INTBIT15, EDOP, NEWJOB, BANKSET and
    PUSHLOC for the interpretive ones.

  See `lm-p34p74-checks.log`.
- **C64 execution results.** Run `make vice-lm-p34p74`. Two PRGs each
  register only the routines their cases reach:
  - group 1: every entry but two (512 cases);
  - group 2: P34/P74E's INTPRET return (SIN, COS) and S34/35.2's return
    (ABVAL) (128 cases).

  Each keeps the image in the RAM under KERNAL ROM (`$01=$35`). The case
  generator is integer-only, so the C64 builds the same entry images as the
  host. In VICE (PAL, stock ROMs) the two PRGs pass 512 and 128 checks
  with no failures (`lm-p34p74-results.json`).

## Limits

- S33/34.1, ELCALC and S34/35.2's ACOS and Lambert setup are not covered.
  The file stays `partial`.
- AVFLAGA, AVFLAGP and P20FLGON belong to P32-P35_P72-P75 and are stops
  here, as are lm-p34-transfer's DISPLAYE and VNPOOH.
- Numerical validity is the original's. No wider claim is made.
