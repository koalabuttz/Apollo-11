# Translate Luminary P40-P47

Lane F (LM powered flight and DAP). Milestone `lm-p40-p47`. How the routines are made and checked: `docs/INTERP-COMPILE.md`.

`Luminary099/P40-P47.agc` (`src/lm_p40_p47.c`, generated by `tools/interp_compile.py lm-p40-p47`) is native C, every word of it. The file holds the thrusting programs P40, P41, P42 and P47, their shared burn set-up (the S40.x subroutines: the thrust direction, the time of ignition, the engine on and off tasks, the trim-gimbal set-up), POSTBURN and UPDATEVG.

## Scope

| Luminary099 | Source | Leaves at |
|---|---|---|
| 36,3147 P40LM to 36,3764 | P40, P41, P42, P47, the staging check, POSTBURN, TIGNOW, ENGOFTSK and ENGINOF1-4, REDO6.7 | BANKCALL, PHASCHNG, 2PHSCHNG, FINDVAC, WAITLIST, TASKOVER, ENDOFJOB, GOTOPOOH, TCF BURNBABY, TCF P40ALM |
| 27,2246 S40.1 to 27,3272 | S40.1 (the thrust direction), S40.2,3, S40.8 (the cross-product steering set-up), S40.9, S40.13 (the DV display), S41.1, TRIMGIMB, UPDATEVG, CALCN85, IMPLBURN | as above, ALARM, UPFLAG/DOWNFLAG, TPAGREE, RTB NORMUNX1 |

385 routines (110 basic, 275 interpretive) start at the entries above, at every point another file returns to (BANKCALL, PHASCHNG, FIXDELAY, VARDELAY and display returns), and at every word after a DANZIG (the spec's `resume_keys`): the file runs as jobs, so a DANZIG can find a job waiting and stop at CHANG2, and the Executive resumes the job there. P47BODY (36,3513) is an entry because P47LM's `TC FINDVAC; 2CADR P47BODY` hands it to the Executive, which starts the job there; P47BOD (36,3504), which only `TC P47BOD` in P47BODY reaches, is compiled inside that routine instead of as a resume key of its own. S40.133 (`EXIT` after `DAD GOTO`, nothing branches to it) is its own routine so the word is translated.

## Channel words

The 17 words the partial milestone left out are compiled (`'channels': 'all'`, with `channel_inputs`, as lm-p70-p71-file does). Each is a call to `agc_ch_op` (`include/agc_channel_ops.h`, the one channel model), on the program's `agc_hardware` (`tests/lm_p40_p47_target.c` gives the program one):

| Words | Source | What it writes |
|---|---|---|
| 27,3223 (its EXTEND at 27,3222 was already compiled); 27,3225-3226; 27,3232-3233; 27,3235-3236 | TRIMGIMB: `WAND CHAN12`, `EXTEND; WOR CHAN12`, `EXTEND; WAND CHAN12`, `EXTEND; WOR CHAN12` | the trim-gimbal pitch and roll drive bits (channel 12, `hardware->channel12`) |
| 27,3245-3246 | TRIMGIMB, just before ROLLOVER: `EXTEND; WAND CHAN12` | roll off |
| 27,3261-3262 | PITCHOFF: `EXTEND; WAND CHAN12` | pitch off |
| 36,3570-3571; 36,3573-3574 | ENGINOF3: `EXTEND; RAND DSALMOUT`, `EXTEND; WRITE DSALMOUT` | the engine on/off bits (channel 11, `hardware->channel11`) |
| 36,3603-3604 | ENGINOF3: `EXTEND; WOR CHAN14` | the thrust-drive bit (channel 14 bit 4, `hardware->channel14`) |

The file reads no input channel. `io_channels` names channels 11, 12 and 14 (14 without the IMU CDU and gyro drive bits, which yaAGC's device models act on at once, as `'auto'` would give): each case sets them on both sides and the comparison covers them after the run. The 18 routine keys the partial build had after each untranslated channel word are gone (those words now run inside their routines), so 403 routines became 385.

The Waitlist tasks (TRIMGIMB from R03, PITCHOFF, ENGOFTSK, STARTP47 and the FIXDELAY and VARDELAY return points) run in T3RUPT whatever job is waiting. With `any_fixloc` and `any_newjob`, every basic routine that never names FIXLOC or NEWJOB and never enters the interpreter checks the image with `sane_nv`: any FIXLOC, and NEWJOB -0 (DUMMYJOB idling) as well as +0 or positive; half of their cases put FIXLOC anywhere in erasable and a quarter set NEWJOB -0.

Destinations outside the file (the Executive, Waitlist, restart, flag, alarm and display interfaces, BURNBABY) stop with `EXEC_UNMAPPED` until their files have routines. `RTB NORMUNX1` has no native body yet; the run ends at it.

## Compiler changes

`tools/interp_compile.py` gained what this file needs, and every earlier spec still regenerates byte-identical (`--check`):

- `Z` read as an operand (`CA Z`, as in POSTBURN) gives the next instruction's address.
- `CALL` with no return point in the file (the interpretive flow ending at NO.9) returns through the caller's QPRET.
- `CALRB` as `CALL`. (`GSHIFT`'s count word and `SLOAD` of a fixed word now use the base compiler's own handling.)
- `tools/interp_routine_differential.py`: the C64 grouper also checks the first routine of a group on its own, so a routine whose whole run does not fit is host-only instead of failing the freeze.

## Refreeze (2026-10-14)

The spec now sets `index_carry16` (INDEX by a negative value keeps its end-around carry on the C64), `image_w` (flight builds address the fixed $7000 image), `c64_rows: 'cover'` (C64 rows chosen by branch outcome over every linked source), `cover_stride` 5, `edge_values` (a quarter of the cases put +-0, one LSB, 1/2, just below 1 and axis vectors in MPAC and the operands, so short runs also take VROUND's and DDV's overflow paths), and `c64_cuts` (arcs that only 180MESS's long runs take get truncated rows, run to a cut on both the oracle and the C64; the diagnostic links `tests/interp_cut.c`).

`tools/interp_routine_differential.py` runs the truncated rows to their cut in the proof's gcov comparison and in `--cover-check` (base's `c64_cuts` support), and, for a `partial` spec, leaves the cases waiting for an I/O channel model (never compared, so no C64 row can take them) out of the host side of that comparison. That last part is gated on `partial` and was added for this spec.

## Refreeze (whole file)

The spec drops `partial` and sets `'channels': 'all'`, `channel_inputs`, `io_channels` (11, 12, 14), `trusted_image`, `any_fixloc` and `any_newjob`, keeping `index_carry16` and `image_w` (the file is not `'basic': 'full'`, so no `fast_window`). The C64 diagnostics build with `-DIRC_CHANNELS -DIRC_INPUTS`. No shared tool changed.

## Evidence

Hashes: `evidence/lm-p40-p47/SHA256.json`.

- **Source map.** `lm-p40-p47-source-map.json` lists all 931 words with the routine that compiles each; none is untranslated.
- **Independent assembly comparison.** `make lm-p40-p47-differential`: 512 states for each of the 385 routines (197,120 cases; NEWJOB is positive in a quarter of them, edge values in a quarter) run the unmodified Luminary099 rope in yaAGC (with the hardware divide) to the same stop. One case loops on both sides (the erasable-CADR cycle, which the AGC runs until the night watchman restarts it) and is counted and left out. All 197,119 compared cases equal it in Z, all 2,048 erasable words, the interrupt-enable state, channels 11, 12 and 14 and the trap flags (`lm-p40-p47-proof.json`). No case waits for a channel and none is refused.
- **Host and sanitizer results.** `make test-lm-p40-p47 sanitize-lm-p40-p47` run the 308 frozen cases (every 640th), 0 failures (`lm-p40-p47-host.log`).
- **C64 execution results.** `make vice-lm-p40-p47` runs 40 diagnostics (routine groups chosen by trial builds that fit below $c000) with 468 cases chosen by `tools/c64_row_cover.py`, 27 of them truncated rows, 0 failures (`lm-p40-p47-vice.log`, one PRG sha256 line per program). No routine is host-only.
- **C64 branch outcomes.** `lm-p40-p47-c64-cover.json`: the C64 rows take all 2,580 gcov branch arcs (every linked source, `include/agc_channel_ops.h` among them) the traced host cases take, and `--cover-check` re-derives it over all compared cases with 0 missing.
