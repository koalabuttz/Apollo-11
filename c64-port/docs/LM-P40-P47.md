# Translate Luminary P40-P47

Lane F (LM powered flight and DAP). Milestone `lm-p40-p47`. How the routines are made and checked: `docs/INTERP-COMPILE.md`.

`Luminary099/P40-P47.agc` (`src/lm_p40_p47.c`, generated by `tools/interp_compile.py lm-p40-p47`) is native C except for the words that write output channels. The file holds the thrusting programs P40, P41, P42 and P47, their shared burn set-up (the S40.x subroutines: the thrust direction, the time of ignition, the engine on and off tasks, the trim-gimbal set-up), POSTBURN and UPDATEVG.

## Scope

| Luminary099 | Source | Leaves at |
|---|---|---|
| 36,3147 P40LM to 36,3764 | P40, P41, P42, P47, the staging check, POSTBURN, TIGNOW, ENGOFTSK and ENGINOF1-4, REDO6.7 | BANKCALL, PHASCHNG, 2PHSCHNG, FINDVAC, WAITLIST, TASKOVER, ENDOFJOB, GOTOPOOH, TCF BURNBABY, TCF P40ALM |
| 27,2246 S40.1 to 27,3272 | S40.1 (the thrust direction), S40.2,3, S40.8 (the cross-product steering set-up), S40.9, S40.13 (the DV display), S41.1, TRIMGIMB, UPDATEVG, CALCN85, IMPLBURN | as above, ALARM, UPFLAG/DOWNFLAG, TPAGREE, RTB NORMUNX1 |

403 routines start at the entries above, at every point another file returns to (BANKCALL, PHASCHNG and display returns), and at every word after a DANZIG (the spec's `resume_keys`): the file runs as jobs, so a DANZIG can find a job waiting and stop at CHANG2, and the Executive resumes the job there. P47BODY (36,3513) is an entry because P47LM's `TC FINDVAC; 2CADR P47BODY` hands it to the Executive, which starts the job there; P47BOD (36,3504), which only `TC P47BOD` in P47BODY reaches, is compiled inside that routine instead of as a resume key of its own. S40.133 (`EXIT` after `DAD GOTO`, nothing branches to it) is its own routine so the word is translated.

Not translated: 17 words, the nine output-channel instructions and the EXTENDs before them (the EXTEND at 27,3222 is compiled):

| Words | Source | What it writes |
|---|---|---|
| 27,3223; 27,3225-3226; 27,3232-3233; 27,3235-3236 | TRIMGIMB: `WAND CHAN12`, `EXTEND; WOR CHAN12`, `EXTEND; WAND CHAN12`, `EXTEND; WOR CHAN12` | the trim-gimbal pitch and roll drive bits |
| 27,3245-3246 | TRIMGIMB, just before ROLLOVER: `EXTEND; WAND CHAN12` | roll off |
| 27,3261-3262 | PITCHOFF: `EXTEND; WAND CHAN12` | pitch off |
| 36,3570-3571; 36,3573-3574 | ENGINOF3: `EXTEND; RAND DSALMOUT`, `EXTEND; WRITE DSALMOUT` | the engine on/off bits (channel 11) |
| 36,3603-3604 | ENGINOF3: `EXTEND; WOR CHAN14` | the thrust-drive bit (bit 4) |

They wait for the shared output-channel model, which the steward assigned to Lane D1. Base has an output-channel record only for whole-file CM basic code (`'basic': 'full'` with `'channels'`, the `cm_native_io` channel fields); the LM interpretive compiler's basic code reads latched input channels (`channel_inputs`) and channels 1-2, and refuses every other channel write. The compiled routines stop with `EXEC_OUT_OF_SCOPE` at these words, and the source map records them as untranslated with that reason. P40-P47 reads no input channel, so `channel_inputs` does not apply. The file stays partial until the output-channel words are translated.

Destinations outside the file (the Executive, Waitlist, restart, flag, alarm and display interfaces, BURNBABY) stop with `EXEC_UNMAPPED` until their files have routines. `RTB NORMUNX1` has no native body yet; the run ends at it.

## Compiler changes

`tools/interp_compile.py` gained what this file needs, and every earlier spec still regenerates byte-identical (`--check`):

- `Z` read as an operand (`CA Z`, as in POSTBURN) gives the next instruction's address.
- `CALL` with no return point in the file (the interpretive flow ending at NO.9) returns through the caller's QPRET.
- `CALRB` as `CALL`. (`GSHIFT`'s count word and `SLOAD` of a fixed word now use the base compiler's own handling.)
- `tools/interp_routine_differential.py`: the C64 grouper also checks the first routine of a group on its own, so a routine whose whole run does not fit is host-only instead of failing the freeze.

## Refreeze (2026-10-14)

The spec now sets `index_carry16` (INDEX by a negative value keeps its end-around carry on the C64), `image_w` (flight builds address the fixed $7000 image), `c64_rows: 'cover'` (C64 rows chosen by branch outcome over every linked source), `cover_stride` 5, `edge_values` (a quarter of the cases put +-0, one LSB, 1/2, just below 1 and axis vectors in MPAC and the operands, so short runs also take VROUND's and DDV's overflow paths), and `c64_cuts` (arcs that only 180MESS's long runs take get truncated rows, run to a cut on both the oracle and the C64; the diagnostic links `tests/interp_cut.c`).

`tools/interp_routine_differential.py` needed two fixes for this spec, both inert for specs without its keys: with `c64_cuts` truncated rows, `gcov_branches` (the proof's `c64_gcov_branches`) and `--cover-check` now run each truncated row to its cut (before, the freeze stopped with an IndexError, and `--cover-check` refused the record); and with `partial`, the cases waiting for an I/O channel model (never compared, so no C64 row can take them) are left out of the host side of that comparison.

## Evidence

Hashes: `evidence/lm-p40-p47/SHA256.json`.

- **Source map.** `lm-p40-p47-source-map.json` lists all 931 words with the routine that compiles each, or the reason it is not compiled (the 17 channel words above).
- **Independent assembly comparison.** `make lm-p40-p47-differential`: 512 states for each of the 403 routines (206,336 cases; NEWJOB is positive in a quarter of them, edge values in a quarter) run the unmodified Luminary099 rope in yaAGC (with the hardware divide) to the same stop. All 196,608 compared cases equal it in Z, all 2,048 erasable words and the interrupt-enable state. The 9,728 cases of the 19 routines that reach a channel write are listed in `lm-p40-p47-proof.json` as `waiting_for_io_channels` and are not compared.
- **Host and sanitizer results.** `make test-lm-p40-p47 sanitize-lm-p40-p47` run the 305 frozen cases (every 640th, so the vectors header stays under 1 MB).
- **C64 execution results.** `make vice-lm-p40-p47` runs 30 diagnostics (routine groups chosen by trial builds that fit below $c000) with 440 cases chosen by `tools/c64_row_cover.py`, 4 of them truncated rows; `lm-p40-p47-c64-cover.json` records that they take every branch arc (gcov, every linked source) the traced host cases take, and `--cover-check` re-derives it over all compared cases with 0 missing (2,439 arcs, the 9,728 channel-waiting cases left out). Routine 27,3123 (180MESS) runs too much code for one diagnostic and is host-only; the arcs only its runs take come from truncated rows.

## Review notes

The file is partial: no certificate is drafted. For whoever reviews it once the channel words land:

- The C64 rows are complete for the compared cases; the 19 channel-waiting routines have no C64 rows (they refuse natively at the channel word).
- P47BOD lost its separate resume key when P47BODY became an entry; the word is still compiled (inside P47BODY's routine), and no outside file reaches P47BOD.
- `cover_stride` 5 was needed because, at 64, every traced case that took OVERFLOW's carry into OVFIND (`lm_interp_orders.c` OVERFLOW) ran too long for one diagnostic; untraced short cases took it.
