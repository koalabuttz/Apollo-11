# Translate Luminary P40-P47

Lane F (LM powered flight and DAP). Milestone `lm-p40-p47`. How the routines are made and checked: `docs/INTERP-COMPILE.md`.

`Luminary099/P40-P47.agc` (`src/lm_p40_p47.c`, generated by `tools/interp_compile.py lm-p40-p47`) is native C except for the words that write output channels. The file holds the thrusting programs P40, P41, P42 and P47, their shared burn set-up (the S40.x subroutines: the thrust direction, the time of ignition, the engine on and off tasks, the trim-gimbal set-up), POSTBURN and UPDATEVG.

## Scope

| Luminary099 | Source | Leaves at |
|---|---|---|
| 36,3147 P40LM to 36,3764 | P40, P41, P42, P47, the staging check, POSTBURN, TIGNOW, ENGOFTSK and ENGINOF1-4, REDO6.7 | BANKCALL, PHASCHNG, 2PHSCHNG, FINDVAC, WAITLIST, TASKOVER, ENDOFJOB, GOTOPOOH, TCF BURNBABY, TCF P40ALM |
| 27,2246 S40.1 to 27,3272 | S40.1 (the thrust direction), S40.2,3, S40.8 (the cross-product steering set-up), S40.9, S40.13 (the DV display), S41.1, TRIMGIMB, UPDATEVG, CALCN85, IMPLBURN | as above, ALARM, UPFLAG/DOWNFLAG, TPAGREE, RTB NORMUNX1 |

403 routines start at the entries above, at every point another file returns to (BANKCALL, PHASCHNG and display returns), and at every word after a DANZIG (the spec's `resume_keys`): the file runs as jobs, so a DANZIG can find a job waiting and stop at CHANG2, and the Executive resumes the job there. S40.133 (`EXIT` after `DAD GOTO`, nothing branches to it) is its own routine so the word is translated.

Not translated: the 17 words of the output-channel instructions, `WAND`/`WOR CHAN12` (the trim-gimbal drive bits in TRIMGIMB, ROLLOVER and PITCHOFF), `RAND`/`WRITE DSALMOUT` (the engine on and off bits in ENGINOF1-4) and `WOR CHAN14`. They wait for an output-channel model in the control-transfer ABI (Lane D1's channel model takes the input channels first); the compiled routines stop with `EXEC_OUT_OF_SCOPE` at them, and the source map records them as untranslated with that reason. The file stays partial until they are translated.

Destinations outside the file (the Executive, Waitlist, restart, flag, alarm and display interfaces, BURNBABY) stop with `EXEC_UNMAPPED` until their files have routines. `RTB NORMUNX1` has no native body yet; the run ends at it.

## Compiler changes

`tools/interp_compile.py` gained what this file needs, and every earlier spec still regenerates byte-identical (`--check`):

- `Z` read as an operand (`CA Z`, as in POSTBURN) gives the next instruction's address.
- `CALL` with no return point in the file (the interpretive flow ending at NO.9) returns through the caller's QPRET.
- `GSHIFT` with a fixed count word, `SLOAD` of a fixed word in the bank (`lmi_sload_fixed`), and `CALRB` as `CALL`.
- `tools/interp_routine_differential.py`: the C64 grouper also checks the first routine of a group on its own, so a routine whose whole run does not fit is host-only instead of failing the freeze.

## Evidence

Hashes: `evidence/lm-p40-p47/SHA256.json`.

- **Source map.** `lm-p40-p47-source-map.json` lists all 931 words with the routine that compiles each, or the reason it is not compiled (17 channel words).
- **Independent assembly comparison.** `make lm-p40-p47-differential`: 256 states for each of the 403 routines (103,168 cases; NEWJOB is positive in a quarter of them) run the unmodified Luminary099 rope in yaAGC (with the hardware divide) to the same stop. All 98,304 compared cases equal it in Z, all 2,048 erasable words and the interrupt-enable state. The 4,864 cases that reach a channel write are listed in `lm-p40-p47-proof.json` as `waiting_for_io_channels` and are not compared.
- **Host and sanitizer results.** `make test-lm-p40-p47 sanitize-lm-p40-p47` run the 305 frozen cases (every 320th, so the vectors header stays under 1 MB).
- **C64 execution results.** `make vice-lm-p40-p47` runs 18 diagnostics (routine groups chosen by trial builds that fit below $bf00) with 768 cases, at least one for every routine.
