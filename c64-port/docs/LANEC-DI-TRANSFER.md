# DISPLAY_INTERFACE_ROUTINES on the transfer ABI

Lane C. Milestone `lanec-di-transfer`.

## What it adds

The six display modules (`lanec-di-dsp`, `-mark`, `-play`, `-sleep`,
`-idle`, `-nvdsp`) were reachable only from their test runners. This
milestone registers every point at which the flight program can enter them
as an `exec_status` routine of the transfer ABI (`docs/NATIVE_TRANSFER_ABI.md`),
so BANKCALL, POSTJUMP, NOVAC/FINDVAC jobs, SPVAC and every callee's return
reach the native code by physical address.

- `src/lanec_di_routines.inc` (generated by `tools/lanec/routines.py di`)
  holds the sorted tables: 165 Luminary099 and 164 Comanche055 entries
  in `lanec_di_lm_routines` / `lanec_di_cm_routines`, plus one table per
  module (`lanec_di_lm_dsp`, ...) for programs that link a subset. Bank 10
  words are at bank*1024+offset; the fixed-fixed BLANKET, ENDMARK and
  CLEARMRK are at 2048+(Z-04000).
- `src/lanec_di_routines.c` wraps each module's dispatch: LM routines take
  `p66_bias_io` (channel 011 from the program's hardware record), CM
  routines take `cm_native_io`. `LANEC_OUT_OF_SCOPE` becomes
  `EXEC_OUT_OF_SCOPE`; superbank, interrupt enable and channel 011 are
  written back.
- `lanec_di_*` is the canonical translation of this file. The older partial
  paths (`p66_*` display helpers, `cm_*` display helpers, `dsky_pinbranch`)
  are superseded and are not registered.

`routines.py di --check` (run by `make test-lanec-di-transfer`) fails unless,
for each mission:

- no address is claimed by two modules;
- every label of the file is registered, except the internal subroutines
  VACDSP, PURRS4, SAVELOCS, SAVELOCR, SKIPADD, GENMARK and RELINTQ, which no
  other source file names, directly or through an EQUALS alias;
- every return point after a TC/TCR to a label outside the file is
  registered (36 per mission, POSTJUMP aside since it never returns:
  SAVELOCS +7, GODSPRS1 +13, BOTHJOBS, and the
  PRIOCHNG, JOBSLEEP, JOBWAKE, ENDIDLE, NVSUB, UPENT2 and DOWNENT2 returns
  among them).

## Round trips

`tests/lanec_di_transfer_cases.c` (suite `di-transfer`, 996 cases) calls
each registered routine from a real caller site: the call site's bank and
Q are set as the caller leaves them, and `agc_transfer_run` follows the
chain through the INTER-BANK routines, the display tables and, for LM, the
Executive (`lm_exec_routines`, `lm_exec_job_routines` with the merged
interbank and exec site operands). A case passes when the run ends at an
unmapped continuation after at least two routines and the complete state
matches the unchanged original program in Virtual AGC run to the same
point. Chains run up to 10 routines (for example BANKCALL, GOFLASH,
SAVELOCS, MAKECADR, MAKEPLAY, NOVAC). BOTHJOBS is reached as SPVAC's
return (68 LM cases) and COPYPACS from NVDSP's `TC COPYPACS` (4 LM cases).

LM cases carry a coherent Executive state (free core sets and VAC areas,
core 0 priority 020000, NEWJOB 0). CM chains stop at the Executive until
Lane A adds Comanche exec routines and `cm_exec_sites`.

The whole round trip does not fit a C64 program, so `di-transfer-c64` runs
the part that does, with only the INTER-BANK, display-start (`lanec_di_*_dsp`)
and MAKEPLAY (`lanec_di_*_play`) routines registered, in both missions
(1,164 cases):

- every caller of a display-start or MAKEPLAY entry (688 cases);
- every display-start and MAKEPLAY point from its own entry, with up to four
  accepted cases of its module (476 cases), so that chains go on past the
  module's exit: BOTHJOBS through SAVELOCR and `TCF BANKJUMP` to the user's
  CADR +4, the MAKEPLAY returns, and on into the fixed-fixed half of the file.

The oracle stops at every point of the other four modules, where this program
has no routine. A chain that ends where the original goes on (inside
INTER-BANK or the file at a point no routine of this program claims, reached
through a module case's random return address) is refused with the state
restored: 1,136 cases are identical and 28 refused. `tools/lanec/cover.py`
picks the 63 cases that together take every branch arc the 1,164 host cases
take into `tests/lanec_di_transfer_c64_c64.h`; they include BANKJUMP, the
SAVELOCS return, fixed-fixed resolution and Comanche055 round trips. The C64
build carries those rows only, one program per mission
(`build/lanec-di-transfer.prg` for Luminary099, `-cm.prg` with
`LANEC_DI_C64_CM`): `make vice-lanec-di-transfer` runs both on a VICE PAL C64
(54 and 9 checks).

## The other four modules on the C64 (`di-transfer-c64m`)

`di-transfer-c64`'s program has no room for the mark, sleep, idle and nvdsp
modules, so `di-transfer-c64m` (1,148 cases) runs their round trips in
programs of their own (certificate review #125):

- every Luminary099 and Comanche055 caller of their entries, as in
  `di-transfer` (POSTJUMP PINBRNCH from FRESH_START, TVCINITIALIZE, P70-P71,
  IMU_CALIBRATION, PINBALL and EXTENDED_VERBS; POSTJUMP MARKEND from
  BLANKET/ENDMARK; BANKCALL GOMARK*, GOXDSPF*, ENDMARK, KLEENEX, INITDSP...),
  through INTER-BANK's BANKCALL, POSTJUMP and SWRETURN;
- every point of theirs from its own entry, with up to four accepted cases of
  its module.

A case registers INTER-BANK and its destination's module only. A module's
routines run on through some of the other modules' points (a mark display
runs the display-start code to its exits), so the oracle stops at the other
modules' points that the module's own suite never runs through
(`c64m_stops_<mission>_<module>`, from the oracle's `LANEC_TRACE` of
`di-<module>`), which is where the native chain ends too. 1,116 cases are
identical and 32 refused with the state restored: chains that end inside
INTER-BANK or the file at a point only an unlinked module claims, reached
through a module case's random return address.

The C64 runs the rows `tools/lanec/cover.py pick di-transfer-c64m` chose
(`tests/lanec_di_transfer_c64m_c64.h`), one program per module and mission
(`build/lanec-di-transfer-<module>-<lm|cm>.prg`, macro
`LANEC_DI_C64M_<MODULE>_<LM|CM>`; `routines.py di` writes each program's rows
to `tests/lanec_di_transfer_c64m_rows.h`). `make vice-lanec-di-transfer-c64m`
runs all eight.

The host suite `di-transfer` has no C64 program of its own (with the
Executive the round trip does not fit one). The certificate's
`c64_branch_outcomes` record (`cover.py record --pool`) lists it with no rows
(`tests/lanec_di_transfer_c64.h`), so each of its host branch arcs must be
taken by some other suite's C64 rows.

## Refusals

`tests/lanec_di_refuse_cases.c` (suite `di-refuse`, 384 cases) takes cases
of the six module suites and breaks the entry contract (BB/FB mismatch,
nonzero ZERO, the wrong bank for a bank 10 entry). Every case must be
refused with the image and I/O unchanged (`diff.py --refusals-only`).

## Other changes

- `src/lm_interbank.c` (Lane A): BANKJUMP no longer refuses Q below 0100.
  SAVELOCS reaches it by `TC L` with Q = 2, and BANKJUMP only exchanges Q as
  debris. The data-address helper still checks Q itself. Lane A's
  interbank suites pass unchanged.
- `tools/lanec/oracle.c` takes a host-only `stop_list`; `include/lanec_case.h`
  allows 8 ranges.
- `tools/lanec/diff.py --refusals` / `--refusals-only`, `native --entries`.
