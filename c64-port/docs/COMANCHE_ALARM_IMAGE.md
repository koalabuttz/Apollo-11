# Comanche alarm caller words and source entry state

`cm_alarm_image` qualifies original ALARM5650, VARALARM5764, CURTAINS5757 and BORTENT5655 over ordinary compiled TC caller descriptors0100..7775. Existing frozen `cm_alarm_record` remains byte unchanged. Actual ALARM reads its inline word after storing Q in ALMCADR; an erasable inline alias to ALMCADR therefore reads the newly stored descriptor. Other RAM words are read before subsequent alarm-record stores, including aliases to ALMCADR+1 or FAILREG. Banked program words must occupy ordinary physical storage>=0100; CPU, editing and hardware counter registers are excluded as compiled inline instruction storage.

`cm_alarm_fixed_address` resolves actual fixed-fixed or current-bank/SUPER inline addresses before the caller loads the passive immutable original data payload. The callee receives that original15-bit word as data. It never decodes that word or uses it to dispatch native code. The passive reader is the previously committed original-layout Comanche data service, whose full40960-address stock C64 result was independently compared word for word under both incoming IRQ contexts. Preserving those words confers no executable algorithm coverage.

BORTENT's first instruction is TS L and it does not itself INHINT. When its record body overflows and hands off to POODOO before RELINT, this additive wrapper preserves incoming virtual IRQ. The older kernel's BORTENT corpus entered under IRQ0; its frozen bytes and proofs are untouched. All other entries execute their real INHINT, and ordinary returns execute RELINT. VARALARM/BORTENT require normal sign-extended incoming A; malformed raw overflow leading to reserved-register returns remains outside this compiled caller contract. PRIOLARM raw-register behavior has a separate retained source qualification.
