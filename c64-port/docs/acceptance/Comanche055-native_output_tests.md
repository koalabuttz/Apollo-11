This is the `native_output_tests` evidence of the `integrated_applications.Comanche055` entry (docs/port-coverage.json). It takes each output Comanche055 drives (`docs/acceptance/Comanche055-native-output-map.json`): the DSKY, the downlink lists on channels 34 and 35, and the output channels (RCS jets on 5 and 6; engine, lamps and alarms on 11; CDU, optics, radar, gimbal and TVC enables on 12; radar and downlink control on 13; CDU, gyro and thrust drives on 14). For each it shows the run that compares the native output with the reference:

- **Downlink**: `tools/flight_downlink_check.py --vice`. On the host, the native word stream matches yaAGC's in lockstep through each restart scenario; on the C64, DOWNRUPTs taken from a snapshot give the same channel 34/35 words and word-order bits as yaAGC from the same state.
- **Output channels**: `tools/flight_scenario_vice.py --replay`. The host's inputs are replayed on the C64 and its erasable words and channels 5, 6, 11-14, 34 and 35 are compared with the host's at each checkpoint (the host matches yaAGC on the same inputs: the integrated_program_tests doc). A row counts a window only when one of its channels changes in the host's states up to the last checkpoint the C64 matched, so the window drove that output.
- **Erasable dump (V74)**: `tools/flight_scenario_vice.py --replay --downrupt`. The window is compared as an output channel window, with DOWNRUPTs on both sides, and the host's states show DNTMGOTO in the dump code (DNDUMPI, DNDUMP, DNDUMP1) by the last checkpoint the C64 matched.
- **DSKY**: `tools/dsky_sweep_vice.py --cases all --replay-exact` on both missions (acceptance bar item 6): every flight noun x display verb and the other key sequences of tools/dsky_sweep_cases.py from one snapshot, each C64 end state compared with the host's over every erasable word and output channel. Its summary counts on this program's store only.

A result from a commit with other port sources (src, include, platform, tools, tests) is stale and counts as not run.
