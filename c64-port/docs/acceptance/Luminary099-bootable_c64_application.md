# Luminary099: bootable C64 application

Generated by `tools/boot_acceptance.py lm` at commit `baf974b9dfa7`. Result: **PASS**.

This is the `bootable_c64_application` evidence of the `integrated_applications.Luminary099` entry (docs/PORT_SCOPE.md). It shows the whole program booting on a stock C64 from its disk images alone, with nothing else prepared on a PC: the loader fills a 2 MB REU from the disks, the flight resident verifies the store and starts the AGC with the hardware restart (GOJAM), and the crew's keys then select P00 on the DSKY on the C64 screen.

Every run below is in VICE (x64sc, PAL, true drive emulation, stock 1 MHz C64, 2 MB REU, the Commodore KERNAL, BASIC and character ROMs). Each one types RSET, `V37` ENTR `00` ENTR after the boot and passes only when the AGC is in P00: MODREG 00000 and `00` under PROG on the screen. Speed and real time are not acceptance criteria (docs/PORT_SCOPE.md); the times are given to say what to expect. Users' steps: docs/RUN-ON-C64.md.

Load is the loader reading and expanding the disks into the REU (from its own CIA count, PAL cycles); the store check is the flight resident verifying every module header and CRC, the resolver and the rope's site words before the GOJAM. The KERNAL's own load of the 6 KB loader adds about 10 s. A disk asked for twice is the loader asking again after a read it did not accept (a wrong disk or a read error), as it does on real hardware; the load then went on. Boot status 0 means every store check passed. Each boot record (`lm-<run>-boot.json`, written by `flight_disk.py --p00`) binds the commit, the disk images, the loader and resident PRGs, the REU store image and the VICE log by SHA-256.

The digits are what the AGC sent to the DSKY relays (channel 10, through T4RUPT); the lamps are channel 11's, row 12's and the restart flip-flop. Lit lamps show in yellow on the screen, so the text above shows every label.

## Keyboard

In the `1581-keyboard` run the keys are pressed on VICE's window through the X server (XTEST), so they reach the AGC the way a user's do: the C64's keyboard scan reads the CIA matrix 25 times a second and queues each DSKY key, and the AGC takes it at its next idle as a KEYRUPT. RSET, `V37` ENTR `00` ENTR reached P00: yes. The key map (docs/RUN-ON-C64.md, The DSKY): `0`-`9`, `+`, `-`, `V` VERB, `N` NOUN, RETURN ENTR, `C` or DEL CLR, `R` RSET, `K` KEY REL, `P` PRO.

## In CI

Every port-ci run whose changes touch the boot path (the watch list in tools/mk/ci-extra.mk: the disk tool, the loader, the drive code, the decompressor, the resident's main) runs `make flight-disk-vice`: the `1581` run above for both programs, and the check disk. It fails unless both reach P00 and the check passes. The run keeps the boot records (`flight-disk-boot-<m>.json`), their VICE logs and the disk images it booted in its `c64…-logs` artifact.
