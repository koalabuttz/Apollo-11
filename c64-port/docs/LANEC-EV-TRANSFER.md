# EXTENDED_VERBS on the transfer ABI

Lane C. Milestone `lanec-ev-transfer`.

## What it adds

The eight extended-verb modules (`lanec-ev-front`, `-short`, `-align`,
`-radar`, `-dap`, `-time`, `-track`, `-lmi`) were reachable only from their
test runners. This milestone registers every point at which the flight
program can enter them as a routine of the transfer ABI
(`docs/NATIVE_TRANSFER_ABI.md`), as `lanec-di-transfer` did for the display
interface.

- Each module's routines are in its own source file,
  `src/lanec_ev_<module>_routines.c` (generated by `tools/lanec/routines.py
  ev`), as sorted tables, one per mission: 313 Luminary099 basic routines
  over the seven basic modules' `lanec_ev_lm_<module>` tables, 29 Luminary099
  interpretive routines in `lanec_ev_lm_interpretive` (`ev-lmi`'s file; keyed
  by LOC under BANKSET at NEWOPS), and 241 Comanche055 basic routines over
  six `lanec_ev_cm_<module>` tables (`LANEC_EV_LM_TABLES` /
  `LANEC_EV_CM_TABLES` list the basic tables). One file per module makes
  each module its own flight-store module, so its link closure is that
  module's code: the basic modules fit the 16 KB job slot (5-12.6 KB on base
  4e5cdfbb; Comanche's whole file as one module was 29 KB over). `ev-lmi`
  links the Luminary interpretive orders and is 14 KB over; interpretive
  modules wait on the interpreter decision.
- `src/lanec_ev_routines.c` runs a module's dispatch on the mission's device
  record (`lanec_ev_run_lm` / `lanec_ev_run_cm`). The modules use
  channels 12, 14, 30, 31 and 33 as well as the superbank and interrupt
  enable, so the routines take the mission's downtelemetry device record,
  which carries them: `lm_dntm_io` (its first member is the `p66_bias_io` that
  the INTER-BANK and Executive routines read, so one record serves the whole
  program) and `cm_dntm_io` (its `cm_native_io` first). As for the display
  interface, Luminary's channel 11 comes from `program->hardware`.
- `lanec_ev_lm_intpret` (in `ev-lmi`'s file) registers INTPRET (fixed-fixed 06037) for this file's
  `TC INTPRET` callers only: it runs INTPRET's few instructions (RELINT, QXCH
  LOC, BANKSET/INTBIT15/EDOP from BB, TCF NEWOPS) when Q names one of the
  interpretive routines above and refuses any other Q. A general INTPRET
  routine belongs to the interpreter's file, which has none yet.
- The `ev-lmi` entries that began at INTPRET now begin at NEWOPS with LOC at
  the first interpretive word, where INTPRET leaves it, so each interpretive
  entry is a LOC point.

`routines.py ev --check` (run by `make test-lanec-ev-transfer`) fails unless,
for Luminary099:

- no point is claimed by two modules;
- every label of the file is registered, except LST2FAN (the verb fan,
  compiled into GOEXTVB), counting a label as named outside the file when it
  or an EQUALS alias of it appears in another file's code;
- every return point after a TC/TCR to a label outside the file is
  registered (143), the verb fan's TC words and POSTJUMP (which never
  returns) aside.

For Comanche055 it lists what is still open: the six returns from
`TC INTPRET` into the interpretive words that wait for the CM interpreter
library.

## Round trips

`tests/lanec_ev_transfer_cases.c` (suite `ev-transfer`, 468 cases) starts at
every genuine BANKCALL/POSTJUMP site whose CADR names an extended-verb
entry, with up to 64 accepted cases of the destination's suite: Pinball's
`POSTJUMP GOEXTVB` with the verbs of the front suite's cases (both
missions), Pinball's `BANKCALL CHKPOOH`, the CM `POSTJUMP GOPIN` from
P40-P47, and the file's own BANKCALL/POSTJUMP sites (AURLOKON, R33,
DAPDISP1, TRMTRAK1, DAPDATA1, DSPRRLOS, STIKLOAD). `agc_transfer_run` runs
INTER-BANK, the display-interface and extended-verb tables, and for
Luminary099 the Executive, INTPRET for this file and the interpretive
routines; CM superbank CADRs (banks 30-33 called from banks 40-43) resolve
to banks 40-43. A case passes when the run ends at an unmapped continuation
after at least two routines and the complete state matches the unchanged
original program in Virtual AGC run to the same point: the oracle runs the
file's words (generated ranges), INTER-BANK, the display interface, the
Executive and the interpreter, stopping at NEWOPS once LOC leaves the
translated interpretive words. LM chains end at the Executive's idle loop,
the display interface's end, a NEWOPS outside the file or Pinball; CM chains
at Pinball or the Executive.

The CM `GOPIN` round trips reach PINBRNCH (lanec-di-nvdsp) with COPINDEX
outside 0-2, which PINBRNCH never reads. The display module now refuses an
out-of-range COPINDEX only in the steps that index with it (NVDSP +1,
GOANIDLE +8, ISITN00, FIRSTOR2ND +4), as `lanec-di-idle` does; `di-nvdsp`
gained 400 cases with COPINDEX above 2 (114 refused unchanged, the rest
identical to the original).

`ev-transfer-c64` (64 Luminary099 `POSTJUMP GOEXTVB` cases) registers only
INTER-BANK and the front routines, and the oracle stops at every other
extended-verb entry; `make vice-lanec-ev-transfer` runs all 64 on a VICE PAL
C64 (link-time optimization drops the unregistered modules).

## Refusals

`tests/lanec_ev_refuse_cases.c` (suite `ev-refuse`, 512 cases) takes cases of
the eight module suites and breaks the entry contract (BB/FB mismatch,
nonzero ZERO, FB selecting bank 7). Every case is refused with the image and
I/O unchanged (`diff.py --refusals-only`).
