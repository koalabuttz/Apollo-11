# Compile P20-P25 into transfer routines (Luminary099)

Lane B (orbital math). Milestone `lm-p20-p25`. How the routines are made and checked: `docs/INTERP-COMPILE.md`.

`Luminary099/P20-P25.agc` (`src/lm_p20_p25.c`, 3,254 words in banks 02, 03, 23-26 and 30-33) is native C in full, as 998 routines of the control-transfer ABI. It is the LM's rendezvous navigation: P20 and P22 (rendezvous and lunar-surface navigation), P25, the R21 and R22 radar designate and data-read routines, R29 (rendezvous radar designate during powered flight), V67 (the W-matrix display), the RR and LR read, designate, remode and reposition routines, and the radar channel bookkeeping.

## Scope

- **Entries.** PROG20 and PROG25 (FRESH_START's program table); FLIP (P70-P71's TC); R21LEM2, SETRRECR and RROUT (BANKCALL CADRs); REMODE, BEGDES and RGOODEND (WAITLIST tasks); R29RDJOB and R29DODES (NOVAC jobs); and R21LEM, R22LEM, CLRADMOD, DORREPOS, GOTOV56, LRALT, LRPOS2, LRVEL, LRVELX, LRVELY, LRVELZ, P20LEMC1, P25LEM1, R12LITES, R22RSTRT, R29, RADAREAD, RRDESNB, RRLIMCHK, RRRANGE, RRRDOT, RRTURNON, RRZERO, SETTRKF and V67CALL, each keyed by its physical address in `lm_p20_p25_interpretive` or `lm_p20_p25_basic`.
- **Resumes.** Every branch target, CALL/STCALL return, EXIT, TC INTPRET point and return from an outside TC is a routine, and so is the word after every DANZIG (`resume_keys`).
- **Channels.** The channel instructions (RAND, WAND, WOR and RXOR on channels 12, 13, 14 and 33, RXOR LCHAN on L, and ROR SUPERBNK on channel 7) run on the shared I/O channel model (`'channels': 'all'`, `include/agc_channel_ops.h`): outputs in the program's `agc_hardware`, inputs in the run's latched channels. The file names no channel 010 or 015.
- **Caller's inline words.** RRLIMCHK's `EXTEND; INDEX Q; INDEX 0` and INITREAD's `INDEX Q; CAF 0` read the word after the caller's TC (spec `inline_reads`). The compiler knows every TC to the subroutine in the rope, including the ones that enter it through a word that falls into it (`TC INITREAD -1`), and picks the word by the return in Q. Any other Q is refused.
- **Leaves at.** NEWOPS with LOC outside the file, the interpreter's POODOO1/ALARM1 exits, and the outside basic routines (BANKCALL, IBNKCALL, POSTJUMP, PHASCHNG, 2PHSCHNG, WAITLIST, FIXDELAY, VARDELAY, TASKOVER, FINDVAC, NOVAC, ENDOFJOB, JOBSLEEP, JOBWAKE, UPFLAG, DOWNFLAG, ALARM, PRIOCHNG, SPSIN, SPCOS, MAKECADR, KILLTASK, TWIDDLE, BLANKET, GOTOPOOH and the rest of the proof's `boundary`).

## States the cases start from

As in every compiled file, each case is a random 2,048-word image with the routine's legal entry state, the input channels drawn from its seed (`channel_inputs`) and the output channels the file names set on both sides (`io_channels`). TIME2/TIME1 and the CDUs vary (`counters`), a quarter of the cases take the edge shape of `tools/edge_cases.py`, and a resume LOC starts from the state the original program is in when it gets there (`resume_flow`). This file also fixes:

- the INDEX MPAC tables after LPS20.2 (`P20LEM1`), LRS22.1 and LRS22.2: MPAC 0, 1 or 2, as those routines return it;
- LRVEL's A, the beam's VBEAM index 0, 2 or 4 (SERVICER's `2XVSELECT`);
- SPCOS's return to `TS SAVECDUT +1` (A without overflow) and R29's pass flag TANG (0 or 1);
- DESCOUNT, the designate time limit, and PIPCTR, SERVICER's pass count (7 down to 0), never -0. R29's CCS PIPCTR on -0 would skip into WAITLIST's inline 2CADR.
- For DESCOUNT: MOREDES counts it down from positive. On -0, STDESIG1's CCS would skip into the WAND after its EXTEND, run it unextended as a TC into erasable, and loop there (yaAGC times out);
- LITIT +3's Q and ITEMP6 (LITIT's saved caller return), V67's W-matrix loop registers, RR1AXIS's axis index and X1 at R21LEM12's STORE.

The oracle is yaAGC without its IMU and optics device models (`'engine': 'flight-device'`). RROUT's `WOR CHAN14` sets the RR CDU drive bits, and the full engine's optics model then dumps CDUT and CDUS (its OPTY and OPTX) at once, which the LM hardware does not do.

## Evidence

Hashes: `evidence/lm-p20-p25/SHA256.json`. Bulk files are assets of the `evidence-lm-p20-p25` release.

- **Source map.** `lm-p20-p25-source-map.json` lists every word: 3,152 compiled routine words and 102 constants that basic code and fixed operands read. None is untranslated.
- **Independent assembly comparison.** `lm-p20-p25-proof.json` and `lm-p20-p25-differential.log`, made by `make lm-p20-p25-differential`. 128 states per routine (127,744 cases) equal yaAGC in Z, all 2,048 erasable words, the interrupt-enable state, the I/O channels 12, 13 and 14 and the HANDRUPT trap flags. Every 128th case is frozen in `tests/lm_p20_p25_vectors.h`.
- **Host and sanitizer results.** `make test-lm-p20-p25 sanitize-lm-p20-p25` runs the 998 frozen cases (`lm-p20-p25-host.log`).
- **C64 execution results.** `make vice-lm-p20-p25` runs 39 diagnostics with 1,350 cases in VICE (`lm-p20-p25-vice.log`). The image lives in the RAM under KERNAL at $e000, and the programs build without inlining, with a static stack and with 110 zero-page bytes.
- **C64 branch outcomes.** `lm-p20-p25-c64-cover.json`: the C64 cases are the fewest that take every gcov branch arc the 127,744 host cases take over all 13 linked sources (`'c64_rows': 'cover'`, `tools/c64_row_cover.py`). All 6,347 host arcs are taken on the C64; none is host-only.
