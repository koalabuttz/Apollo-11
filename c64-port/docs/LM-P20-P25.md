# Compile P20-P25 into transfer routines (Luminary099)

Lane B (orbital math). Milestone `lm-p20-p25`. How the routines are made and checked: `docs/INTERP-COMPILE.md`.

`Luminary099/P20-P25.agc` (`src/lm_p20_p25.c`, 3,254 words in banks 02, 03, 23-26 and 30-33) is native C in full, as 1,026 routines of the control-transfer ABI. It is the LM's rendezvous navigation: P20 and P22 (rendezvous and lunar-surface navigation), P25, the R21 and R22 radar designate and data-read routines, R29 (rendezvous radar designate during powered flight), V67 (the W-matrix display), the RR and LR read, designate, remode and reposition routines, and the radar channel bookkeeping.

## Scope

- **Entries.** PROG20 and PROG25 (FRESH_START's program table); FLIP (P70-P71's TC); R21LEM2, SETRRECR and RROUT (BANKCALL CADRs); REMODE, BEGDES and RGOODEND (WAITLIST tasks); R29RDJOB and R29DODES (NOVAC jobs); and R21LEM, R22LEM, CLRADMOD, DORREPOS, GOTOV56, LRALT, LRPOS2, LRVEL, LRVELX, LRVELY, LRVELZ, P20LEMC1, P25LEM1, R12LITES, R21LEM12 +12, R22RSTRT, R29, R29LOKON, RADAREAD, RRDESNB, RRLIMCHK, RRRANGE, RRRDOT, RRTURNON, RRZERO, SETTRKF and V67CALL, each keyed by its physical address in `lm_p20_p25_interpretive` or `lm_p20_p25_basic`.
- **Resumes.** Every branch target, CALL/STCALL return, EXIT, TC INTPRET point and return from an outside TC is a routine, and so is the word after every DANZIG (`resume_keys`).
- **Channels.** The channel instructions (RAND, WAND, WOR and RXOR on channels 12, 13, 14 and 33, RXOR LCHAN on L, and ROR SUPERBNK on channel 7) run on the shared I/O channel model (`'channels': 'all'`, `include/agc_channel_ops.h`): outputs in the program's `agc_hardware`, inputs in the run's latched channels. The file names no channel 010 or 015.
- **Caller's inline words.** RRLIMCHK's `EXTEND; INDEX Q; INDEX 0` and INITREAD's `INDEX Q; CAF 0` read the word after the caller's TC (spec `inline_reads`). The compiler knows every TC to the subroutine in the rope, including the ones that enter it through a word that falls into it (`TC INITREAD -1`), and picks the word by the return in Q. Any other Q is refused.
- **Returns inside the file.** MAGSUB, RRLIMCHK and RRLIMNB return to TC Q+1 or Q+2 of their callers in the file (`in_file_returns`), so each return word is a routine. The native code still stops at MAGSUB's Q+1 and Q+2 words (INTERPRETER's 06737 and 06741), and the return word's own routine runs on from there.
- **Basic key stops (`basic_key_stops`).** A basic routine runs only to the next word that is a basic key of the file, sets Z there and returns, instead of running on through the whole flow. The routines are smaller, so the file splits into flight store chunks. Whether a routine takes any FIXLOC (below) still comes from its whole flow.
- **Direct ABI (`direct_abi`).** The routines take the program, the state and the I/O block directly, and the table points at them. The checks that the transfer ABI wrapper made (`entered`) run inside each routine's entry check (`e_at_basic`, `e_at_newops` and the rest). That saves a wrapper per routine: 213 KB of C64 code instead of 320 KB.
- **Leaves at.** NEWOPS with LOC outside the file, the interpreter's POODOO1/ALARM1 exits, and the outside basic routines (BANKCALL, IBNKCALL, POSTJUMP, PHASCHNG, 2PHSCHNG, WAITLIST, FIXDELAY, VARDELAY, TASKOVER, FINDVAC, NOVAC, ENDOFJOB, JOBSLEEP, JOBWAKE, UPFLAG, DOWNFLAG, ALARM, PRIOCHNG, SPSIN, SPCOS, MAKECADR, KILLTASK, TWIDDLE, BLANKET, GOTOPOOH and the rest of the proof's `boundary`).

## States the cases start from

As in every compiled file, each case is a random 2,048-word image with the routine's legal entry state, the input channels drawn from its seed (`channel_inputs`) and the output channels the file names set on both sides (`io_channels`). TIME2/TIME1 and the CDUs vary (`counters`), a quarter of the cases take the edge shape of `tools/edge_cases.py`, and a resume LOC starts from the state the original program is in when it gets there (`resume_flow`). This file also fixes:

- the INDEX MPAC tables after LPS20.2 (`P20LEM1`), LRS22.1 and LRS22.2: MPAC 0, 1 or 2, as those routines return it;
- LRVEL's A, the beam's VBEAM index 0, 2 or 4 (SERVICER's `2XVSELECT`);
- SPCOS's return to `TS SAVECDUT +1` (A without overflow) and R29's pass flag TANG (0 or 1);
- DESCOUNT, the designate time limit, and PIPCTR, SERVICER's pass count (7 down to 0), never -0. R29's CCS PIPCTR on -0 would skip into WAITLIST's inline 2CADR.
- For DESCOUNT: MOREDES counts it down from positive. On -0, STDESIG1's CCS would skip into the WAND after its EXTEND, run it unextended as a TC into erasable, and loop there (yaAGC times out);
- G+N,AUTO's A at R61LEM1 +21: 0, 0777 (CCS of BIT10 outside G+N) or BIT14 (outside AUTO);
- LITIT +3's ITEMP6, R12LITES's own return after TC HLIGHT (25,3614) or TC HLIGHT -3 (25,3615), so the case runs on through R12LITES to ISWRETRN (the Q it swaps out is never read again: LODSAMPT's address stands in, outside the file);
- X1 at R21LEM12's STORE,1: INTEXIT's -2 (earth) or -10D (moon), which LPS20.1's CSMCONIC/LEMCONIC leaves in the job, and 0-6 besides;
- V67's W-matrix loop registers (X1 6-54, S1 6), RR1AXIS's axis index RRINDEX (0 or 1), R22LEM96's N49FLAG and NEWJOB together, and HFLSHBIT's index (0 for H, -1 for V);
- the words that some arms read but random images rarely take (reviewer 1, #491). Each list also keeps the case's own random value (`'any'`) in some cases. The words are SAMPLIM (0, for the +0 arms and DATAFAIL), MODREG (P20 and P22), OPTION2, RADCADR, NSRCHPNT (6), ITEMP1 (RR1AX2 +17, GOODRAD; past 384 either way at RROUT2 +6, RROUTLIM's clamp, and within it at SETRRCTR), RNRAD (VELCHK, LRHEIGHT, with and without bit 15) and A at 32,2641/2644/2652. They also include the counter words 0154/0155 at DONBRD +58 and LOSCOUNT under the case's EBANK at NOTP20 (`'E:1456'`). ITEMP2 at RROUT2 +6 and SETRRCTR is 0 or 1, as RRDESNB's INDEX ITEMP2 needs. Three CHANG2 resumes, whose cases start from the state the program reaches there (`resume_flow`), take these values in half their cases instead (`resume_states`, reviewer 1, #545): LRS22.1's DSU BMN (32,2522) an angle below THREEDEG in MODE DP, its good-data exit to NORMEXIT; V67's BOV (30,2032) OVFIND clear, the RMS values in range; R22LEM96's BZE (24,2606) MPAC 0, the N49 display not yet answered, so BZE -3 reads N49FLAG again. The supported domain holds LOSCOUNT to 0-3 at NOTP20 (auditor, #508).

Two CCS +0 arms are never taken: 25,2756 (CCS MPAC) and 25,3624 (CCS A). 25,2756 tests a DOT result plus -cos 0.5° (DAS, with high word -07777), and 25,3624 tests ITEMP1 - 16. A ones'-complement sum is +0 only when both addends are +0, and neither can overflow positive, so their zero is always -0 and the cases that reach them take the -0 arm (reviewer 1 checked yaAGC's DAS, #545).

**FIXLOC and NEWJOB (`any_fixloc`, `any_newjob`).** The WAITLIST, TWIDDLE, FIXDELAY and VARDELAY tasks (REMODE, BEGDES, RGOODEND, RRZ2, LRPOSCAN, CALLDGCH, PREPOS29, BEGDES29, R29READ, R21LEM9, R61C+L2, P20LEMC1, P20LEMD1, P25LEM2 and the RR1AX2, DESLOOP and R29DLOOP loops), the RADARUPT and T4RUPT callers (RADAREAD, RRLIMCHK, SETTRKF, RRTURNON, DORREPOS, FLIP) and the NOVAC jobs (N49DSP, R29REMOJ, R29RDJOB, R29DODES) run without a VAC area. R29DODES sets FIXLOC to R29FXLOC (052) itself, and its resumes run under it. So every basic routine that neither enters the interpreter nor indexes through FIXLOC (401 of them, `novac()` in `tools/interp_compile.py`) takes any FIXLOC and NEWJOB -0 too (`sane_nv`). In the cases, each takes a FIXLOC outside the VAC areas in at least 49 of its 128 (25,647 in all) and NEWJOB -0 in at least 17 (12,862). The 77 basic routines that enter the interpreter, and the interpretive ones, keep a VAC area.

The oracle is yaAGC without its IMU and optics device models (`'engine': 'flight-device'`). RROUT's `WOR CHAN14` sets the RR CDU drive bits, and the full engine's optics model then dumps CDUT and CDUS (its OPTY and OPTX) at once, which the LM hardware does not do.

## Evidence

Hashes: `evidence/lm-p20-p25/SHA256.json`. Bulk files are assets of the `evidence-lm-p20-p25` release.

- **Source map.** `lm-p20-p25-source-map.json` lists every word: 3,152 compiled routine words and 102 constants that basic code and fixed operands read. None is untranslated.
- **Independent assembly comparison.** `lm-p20-p25-proof.json` and `lm-p20-p25-differential.log`, made by `make lm-p20-p25-differential`. 128 states per routine (131,328 cases) equal yaAGC in Z, all 2,048 erasable words, the interrupt-enable state, the I/O channels 12, 13, 14 and 33 and the HANDRUPT trap flags. Every 128th case is frozen in `tests/lm_p20_p25_vectors.h`.
- **Host and sanitizer results.** `make test-lm-p20-p25 sanitize-lm-p20-p25` runs the 1,026 frozen cases (`lm-p20-p25-host.log`).
- **C64 execution results.** `make vice-lm-p20-p25` runs 28 diagnostics with 1,224 cases in VICE (`lm-p20-p25-vice.log`). The image lives in the RAM under KERNAL at $e000, and the programs build without inlining, with a static stack and with 110 zero-page bytes.
- **C64 branch outcomes.** `lm-p20-p25-c64-cover.json`: the C64 cases are the fewest that take every gcov branch arc the 131,328 host cases take over the 14 linked sources and the runner (`'c64_rows': 'cover'`, `tools/c64_row_cover.py`). All 3,657 host arcs are taken on the C64; none is host-only. The proof's `c64_gcov_branches` counts the same arcs without the runner's own 29 (`tools/interp_routine_native.c`): 3,628 on both. There are fewer arcs than before mainly because basic key stops compile each AGC word about once (5,796 copies of 3,167 words, from 15,008); the direct ABI also drops the per-routine wrappers and their checks.
