# Comanche actual task/service composition

`cm_service_loop` is a resident compiled continuation resolver over the sole 2048-word canonical image and explicit CM external I/O. It maps source PC/bank and certified caller metadata to real native source groups. The invoke hook returns its C frame before the next service or overlay replacement. Unknown application bodies remain at their genuine source tuple with an unmapped result. The runtime neither reads executable rope nor declares an unported flight payload complete. Source task bodies, service argument tuples and continuation addresses are compiled from the independently qualified original milestones.

The continuous oracle starts at original T3RUPT2 01,3423 and executes actual SETJTAG, disabled/enabled CLOKTASK and real SVCT3 housekeeping through actual WAITLIST/NOVAC/FIXDELAY/TASKOVER. Six paths cover disabled timer cleanup, periodic clock rescheduling, drift-task completion, real NBDONLY admission and the real delayed SVCT3 recheck. The task loop reaches original 05341 before hardware RESUME. It does not use the older dummy-task completion shortcut. FIXDELAY preserves source AllowInterrupt even when it is one, because source InIsr already prevents nested delivery; its transient external-I/O view introduces no persistent flight-state copy.

All 384 cases/1856 continuous checkpoints compare every 2048 physical word, external SUPERBNK/IRQ, source group and result against sequential original assembly. No source state is reset between checkpoint groups. Host and ASan/UBSan pass the complete corpus, whole-image fingerprints, a complete 2052-value state, callback reentry and unknown-body guards. Snapshot SHA256 is `fd6a0f1cdefdaa0e3d201e763976dd47c2e374a234bd018de6447ddd97284033`. Counter-drive inputs are zero, the source scaler is frozen and no output is normalized. The host-only GPL oracle uses Virtual AGC `1b5d6474841a7ab53237ead070f76f35f162f68d`, byte-original Executive/WAITLIST/CM_ENTRY_DIGITAL_AUTOPILOT/P40-P47 sections with audited indentation-only repairs 5/9/1/7 and pinned corrected supporting sources. Rope SHA256 is `2ba31de9291cd10fb351a64d261bae8514a1cb75b4651bfa6a135dfa821a2d79`. Historical originals are untouched.

PAL C64 standalone qualification passes 64 representative continuous cases/308 complete-image checkpoints plus a complete 2052-value state, mailbox `a500004000`. Its task-body diagnostic uses `CM_SERVICE_TASK_PROOF_ONLY`; longer restart/display/longcall mappings remain independently qualified modules and are not part of this continuous corpus. PRG 32884 bytes, text 26789, rodata 6081, BSS 4122, image end `$988d`, hardware/software stack extents 31/1488 bytes, no extra zero-page sections. The initial full-builtin linkage overflow is retained in the build-attempt evidence. Production resident memory fit is established by the separate real overlay composition, not this standalone diagnostic.

The resolver also registers certified individual TIG-5, LONGCALL/restart selectors, original dynamic GOLOC calls and INITDSP 10,3261/10,3267. These mappings retain actual source arguments and select independently verified bodies; continuous execution through those complete application paths requires their later service/application continuations. It deliberately does not complete TIG-0, S40.13, NBDONLY, CLOCKJOB/DYNDISP, restart RTRNCADR/SWRETURN, idle self-check or pending DANZIG foreground operations. Further milestones register and qualify those actual source bodies.

Native code is MIT. Runtime metadata owns pointers, callback guard and counts outside the canonical image; source caches are transient and producer exclusion is caller-owned. `src/cm_service_builtin.c` supplies normal compiled body calls for the host and standalone diagnostics. The final loader-backed invoke hook replaces that linkage while retaining the same resident resolver and source boundaries.

Export with `python3 tools/cm_service_loop_report.py service-loop`; manifest is `evidence/cm-service-loop-evidence.sha256`.
