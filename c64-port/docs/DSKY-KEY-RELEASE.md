# Both-program key release and actual display wake

`dsky_charin_release` and `cm_charin_release` execute actual CHARIN40,2077/40,2000 for KEYREL031 through VBRELDSP, RELDSP/RELDSP1/RELDSP2 and the source-selected return. They clear uplink activity, distinguish suspended external monitoring, release the display lock, retain or clear the key-release light as the original requests, clear external-monitor ownership on normal release, and execute real JOBWAKE for an occupied DSPLIST. Both matching and absent sleeping jobs return through the original caller; all Executive/core/VAC/NEWJOB and source CPU debris are preserved.

The return reports actual source entry: genuine ENDOFJOB5155/5217, PINBRNCH10,3050/10,3272, or BLNKSUB140,3505/40,3412. PINBRNCH uses the original fixed POSTJUMP, preserving A/L and selecting the real bank. No callback is invoked inside the key body and no additional scheduling check is inserted.

CADRSTOR=-0 is supported. CCS's skip executes the fixed inline CADR as DAS1047/1050 in LM or DAS1271/1272 in CM on the normal release path, then falls through UNSUSPEN into BLNKSUB1. The direct unsuspend path reaches BLNKSUB1 without that DAS. This one historical literal is compiled into native double addition; no runtime AGC instruction decoder or rope lookup is present. The original TC RELRET executes its stored TC descriptor and leaves Q0145 on the normal blank fallthrough; this detail is checked in the full image.

The bounded entry domain is bank40/any EB/SUPER100, IRQ0/1, lawful DSPLOCK0/1 and ordinary source word data. Only selected normal-release paths with DSPLIST nonzero require the separately qualified JOBWAKE context domain: active positive core0, no +0 candidate priorities, valid pending NEWJOB and legal saved bank of the first matching dormant context. Unused Executive data is accepted unchanged; the corpus explicitly includes invalid wake-only fields on no-wake branches. A pending CM Executive alarm is rejected only when that wake path is selected. Every rejection precedes mutation of the source image, I/O and returned route.

CADRSTOR producers were checked in the original sources: STARTSUB clears it, ENDIDLE forms the caller's low10 address plus FBANK, and RECALTST/WITCHONE exchange-clear it. RSET preserves it, including -0. No global assumption that -0 cannot reach KEYREL is made. Source completion still requires executing the returned PINBRNCH and BLNKSUB1 bodies and their continuations, rather than treating these actual source transfers as job completion.

The independent oracle compares8192 complete2053-field original checkpoints:2048 physical words plus SUPER/IRQ/channel11/output event/returned route. It checks matched/missing wakes across every slot, higher-priority wake requests, existing pending jobs, both zero signs, every retained EB, raw L, monitor ownership, and all three actual continuations. Complete stream SHA256:
`b4b238136ffd4000b4727810db2dc038676633641edbae9d3405e0978a70f70b`.
The full ASan/UBSan stream equals the original byte for byte. No native body is linked into the oracle. Original Executive/Pinball/T4/Interpreter/display-interface/fresh-start source bytes and CM indentation-only repairs are audited; both whole assembled ropes must equal their pinned originals. Oracle stopping addresses also check the physical bank so an Executive instruction with the same numerical PC cannot become a false checkpoint.

Frozen64 complete images pass strict host, ASan/UBSan and native C64. VICE PAL mailbox `a500004002`; PRG19199 bytes (loaded19197); hardware/software stack22/767 bytes. Sections remain belowC000 and additional compiler zero-page storage is rejected. `tools/dsky_charin_release.mk` provides portable host-only all/test/sanitize and explicit differential/C64 targets. Evidence uses build/dsky-charin-release-* and build/dsky_charin_release-*.

The caller holds restoring producer exclusion and owns one canonical source image and explicit I/O. Real Executive completion, downstream display continuation and hardware keyboard/output routing remain separate required application stages. This package translates the actual key-release body and reports source-selected transfers; it does not claim a complete Pinball application.
