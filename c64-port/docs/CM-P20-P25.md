# Translate Comanche P20-P25

Lane D1b (alignment and maneuvers). Milestone `cm-p20-p25`. How the routines are made and checked: `docs/INTERP-COMPILE.md`.

`Comanche055/P20-P25.agc` is native C (`src/cm_p20_p25.c`) in 2,714 of its 2,724 words: 2,605 compiled and 109 constants, as 1,139 routines. Each routine runs the file from its entry, or from where it resumes, to the point where control leaves the file. The file is **partial**: 10 words wait for an I/O channel model (below).

## Scope

The entries are every word another file names (`@external`), plus CNTCHK, a label nothing names (STQ POINTEX, then CONTCHK). Every word after a DANZIG or a CALL is a resume routine of its own (`resume_keys`).

| Bank (words) | Source |
|---|---|
| 30 (933) | PROG22 (P22 orbital navigation), the S22 landmark and W-matrix routines (S22NXTU, S22NXTWI, S22NXXA, S22NXXB, S22W76X), 9DWTO6DW and ROWDOT |
| 31 (611) | P23 (cislunar navigation), HORIZ (the horizon-sighting geometry) |
| 34 (603) | R22 (mark processing), RENDISP7, CRS61.1 (R61 tracking), AUTOCK (the trunnion checks), V89CALL |
| 37 (228) | PROG20 (P20 rendezvous navigation), R61CSM |
| 27 (169) | RANGERD and VHFREAD (the VHF range read) |
| 40 (100) | V67CALL |
| 23, 16, 02, 14 (80) | the file's short pieces in other banks, LOWMEMRY (the star-catalog search) among them |

INCORP1 and INCORP2 (MEASUREMENT_INCORPORATION) and the other files' routines are transfer routines outside the file. RTB LOADTIME, TPMODE and DPMODE run natively (`src/rtb_angles.c`, `src/rtb_modes.c`).

## Not native yet: the channel words

These words are left out of every routine (`partial` in the spec) and a case that starts at or runs into them is refused natively, waiting for an I/O channel model:

| Words | Order |
|---|---|
| 27,2420-2421, 27,2423-2424 | RANGERD's EXTEND; WAND CHAN13 and EXTEND; WOR CHAN13 |
| 27,2532-2533 | VHFREAD's EXTEND; RAND CHAN33 |
| 34,3360-3361 | AUTOCK's EXTEND; RXOR CHAN31 |
| 34,3427-3430 | EXTEND; WOR DSALMOUT (channel 11) |

4,606 of the cases are refused this way. The proof lists them (`waiting_for_io_channels`) with the stops the original program takes from them (`io_channel_refused_oracle_outcomes`). Lane D1's Comanche channel model will let these words compile; the file then needs one refreeze.

## Domain

Canonical 2048-word image entered at NEWOPS with LOC at any interpretive routine of the file (or Z at a basic one), FB its bank and EB from the listing's EBANK= (`ebank: 'listing'`). Operand values, the CDUs and the counters vary per case, with edge values in a quarter of them. The pointer and counter cells the code indexes are held to the values the program gives them:

- S22LOC, MARKDATA and MARKSTAT name a mark slot; STARCODE is a catalog code; BESTI a multiple of 6 up to 228 (LOWMEMRY's `VLOAD* CATLOG,1` reads the catalog 228 words below CATLOG, `indexed_fixed`).
- S22's TIX loops (S22NXTU to S22W76X) run with S1 6 and X1 a multiple of 6 up to 36.
- 9DWTO6DW's counters (pushdown 6D-14D) are DP-word indexes, and in the W-matrix pass (9DWI=JA to 9DWEXITX) J and I sit near the loop's end, J never 0 inside the loop, so a run stays short. (J 0 inside it would step past the exit test forever.)
- RENDISP7's TEMPOR1 is -1 or +1, as the display job leaves it.

Resume points start from the original program's state there (`resume_flow`: all 574 resume LOCs). Runs take up to 40,000 routines (`max_steps`).

## Evidence

Hashes: `evidence/cm-p20-p25/SHA256.json`. The source map, logs and VICE log are assets of the `evidence-cm-p20-p25` release (the source map is too big for the tree).

- **Source map.** `cm-p20-p25-source-map.json` lists every word with the routine that compiles it: 2,605 compiled, 109 constants, 10 untranslated (the channel words above).
- **Independent assembly comparison.** `make cm-p20-p25-differential`: 256 states per routine (291,584 cases, 1,139 routines) equal yaAGC in Z, all 2,048 erasable words and the interrupt-enable state (case set 67b3b2b4). The 4,606 channel cases are refused at their first step.
- **Host and sanitizer results.** `make test-cm-p20-p25 sanitize-cm-p20-p25` runs the 1,956 frozen cases (`cm-p20-p25-host.log`).
- **C64 execution results.** `make vice-cm-p20-p25` runs 107 diagnostics with 1,377 cases (`cm-p20-p25-vice.log`, with each PRG's sha256). 49 rows are segment rows (`c64_segments`): the S22 and HORIZ chains run too long for one diagnostic, so these rows run a case from one routine to the next CHANG2 resume LOC.
- **Branch outcomes.** The C64 rows take 4,969 of the 4,986 host outcomes (`cm-p20-p25-c64-outcomes.json`). The 17 left are reached only inside runs too long for one diagnostic, at points no segment row can stop at: five fall-throughs in bank 30 (after 30,2474, 30,2533, 30,2543, 30,2546 and 30,2571, where a TIX goes back to the loop's head before the resume LOC), and twelve divide-overflow, VSC/V/SC and ARCCOS-limit branches of the shared order bodies in `src/lm_interp_orders.c`. The host checks take them all.
