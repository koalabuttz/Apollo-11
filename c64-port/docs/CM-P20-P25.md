# Translate Comanche P20-P25

Lane D1b (alignment and maneuvers). Milestone `cm-p20-p25`. How the routines are made and checked: `docs/INTERP-COMPILE.md`.

`Comanche055/P20-P25.agc` is native C (`src/cm_p20_p25.c`) in all 2,724 of its words: 2,617 compiled and 107 constants, as 1,128 routines. Each routine runs the file from its entry, or from where it resumes, to the point where control leaves the file.

## Scope

The entries are every word another file names (`@external`), plus CNTCHK, a label nothing names (STQ POINTEX, then CONTCHK). Every word after a DANZIG or a CALL is a resume routine of its own (`resume_keys`).

| Bank (words) | Source |
|---|---|
| 30 (933) | PROG22 (P22 orbital navigation), the S22 landmark and W-matrix routines (S22NXTU, S22NXTWI, S22NXXA, S22NXXB, S22W76X), 9DWTO6DW and ROWDOT |
| 31 (611) | P23 (cislunar navigation), HORIZ (the horizon-sighting geometry) |
| 34 (603) | R22 (mark processing), RENDISP7, CRS61.1 (R61 tracking), AUTOCK (the trunnion checks), V89CALL |
| 37 (228) | PROG20 (P20 rendezvous navigation), R61CSM |
| 27 (169) | RANGERD and VHFREAD (the VHF range read) |
| 40 (100) | V67CALL |
| 23, 16, 02, 14 (80) | the file's short pieces in other banks, LOWMEMRY (the star-catalog search) among them |

INCORP1 and INCORP2 (MEASUREMENT_INCORPORATION) and the other files' routines are transfer routines outside the file. RTB LOADTIME, TPMODE and DPMODE run natively (`src/rtb_angles.c`, `src/rtb_modes.c`).

## The channel words

RANGERD's WAND and WOR CHAN13, VHFREAD's RAND CHAN33, and AUTOCK's RXOR CHAN31 and WOR DSALMOUT (channel 11) compile with the rest of the file (`'channels': 'all'`). On a Comanche interpretive file, `tools/interp_compile.py` emits the channel orders through `tools/basic_compile.py`'s per-file channel helpers: channels 011-014 are the program's channel words, and 5, 6 and 030-033 are the mission's `agc_channels_hw` record. The routines take that record from the `cm_native_io` they are called with (a program without one is refused). `'io_channels': 'auto'` gives the cases random values in each channel the file uses, and compares the channels after the run.

## Domain

Canonical 2048-word image entered at NEWOPS with LOC at any interpretive routine of the file (or Z at a basic one), FB its bank and EB from the listing's EBANK= (`ebank: 'listing'`). Operand values, the CDUs and the counters vary per case, with edge values in a quarter of them. The pointer and counter cells the code indexes are held to the values the program gives them:

- S22LOC and MARKSTAT name a mark slot, and MARKDATA a mark slot or (P23.60's `MASK LOW10` of MARKSTAT) a mark VAC area. BESTI is 0 or a multiple of 6 up to 228 (LOWMEMRY's `VLOAD* CATLOG,1` reads the catalog 228 words below CATLOG, `indexed_fixed`).
- STARCODE is any word, since the crew keys it in octal through N70 (P23.06's V05N70): codes 0-40 with high bits set, -0 to -40, and the ends of both signs. P23.16 checks it (`BZF P23.176`, `BZMF R23.10`, 37 and below), so from P23.17 to P23.176 it is a catalog code 1-37.
- S22's TIX loops (S22NXTU to S22W76X) run with S1 6 and X1 0 or a multiple of 6 up to 36.
- 9DWTO6DW's counters (pushdown 6D-14D) are DP-word indexes. The W-matrix pass (9DWI=JA to 9DWEXITX) visits J 58, 56, 54, then (the J=52 test: `9DW26D` is `52 B-14`) 4, 2 and 0, with I counting down from J the same way and N 0-30 in steps of 6. J is 0 only up to the pass's exit test after 9DWAAB; past it J 0 would step past the test forever.
- RENDISP7's TEMPOR1 is -1 or +1, as the display job leaves it, or +0 (the waiting state, RENDISP's `TS TEMPOR1`) with a job waiting, so the `SLOAD BZE` loop-back's DANZIG goes to CHANG2.
- AUTOCK's CDU loop (CDULOOP to STKTEST) runs with DTHETASM 2, 1 or 0, the CDU it is on.
- VHFREAD is the RADAR RUPT handler (INTERRUPT_LEAD_INS; it leaves through TASKOVER, GOODEND or BADEND), and RENDISP2 and ENDR57's ENDMARK are NOVAC jobs. So the basic routines that neither index through FIXLOC nor enter the interpreter take any FIXLOC, and NEWJOB -0 as DUMMYJOB leaves it while the computer idles (`any_fixloc`, `any_newjob`): half and a quarter of their cases set them.

Resume points start from the original program's state there (`resume_flow`: all 574 resume LOCs). Runs take up to 40,000 routines (`max_steps`).

## Evidence

Hashes: `evidence/cm-p20-p25/SHA256.json`. The source map, logs and VICE log are assets of the `evidence-cm-p20-p25` release (the source map is too big for the tree).

- **Source map.** `cm-p20-p25-source-map.json` lists every word with the routine that compiles it: 2,617 compiled, 107 constants, none untranslated.
- **Independent assembly comparison.** `make cm-p20-p25-differential`: 256 states per routine (288,768 cases, 1,128 routines) equal yaAGC in Z, all 2,048 erasable words, the interrupt-enable state and the channels (case set 337c35ef).
- **Host and sanitizer results.** `make test-cm-p20-p25 sanitize-cm-p20-p25` runs the 1,985 frozen cases (`cm-p20-p25-host.log`).
- **C64 execution results.** `make vice-cm-p20-p25` runs 138 diagnostics with 1,459 rows (`cm-p20-p25-vice.log`, with each PRG's sha256). 50 are segment rows (`c64_segments`): the S22 and HORIZ chains run too long for one diagnostic, so these rows run a case from one routine to the next CHANG2 resume LOC. 37 are truncated rows (`c64_cuts`, `tests/interp_cut.h`): a case started next to an outcome only long runs take, run to a cut where the oracle stops too.
- **Branch outcomes.** The rows are chosen by gcov branch arc over every linked source (`c64_rows: 'cover'`, every 16th case traced). They take all 5,016 arcs the traced host cases take (`cm-p20-p25-c64-cover.json`), and all 6,160 clang edge outcomes the host cases reach (`cm-p20-p25-c64-outcomes.json`).
